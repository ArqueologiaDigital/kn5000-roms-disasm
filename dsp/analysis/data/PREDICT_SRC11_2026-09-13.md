# PRE-REGISTRATION — `SRC 0x11`, swept over its three readings against the anchored cells

Written **before** the run. 2026-09-13.

## The target
`SRC 0x11` is the queue's next entry: **54 sole / 77 occurrences over 29 images**, including **5 in
the resident kernel** and 2 in the output stage — so it is on every program's path. The device
already carries all three readings, selected by the SPEC mask:

| arm | mask | reading |
|---|---|---|
| **A** (shipped) | `b910e446a39b440f` | bit 14 set → `acc_to_datum(cur_unit ? accb : acc)` — the CURRENT unit's accumulator |
| **B** | `b910e446a39b040f` | bit 14 clear, bit 1 set → `acc_to_datum(accb)` — always unit 1's accumulator |
| **C** | `b910e446a39b040d` | both clear → `mem[ptr]` |

`§27` shipped the ACCB family; `§113` proposed `mem[ptr]` and it has sat off since, and `§97` showed
this session that the one test ever run on it was aimed at a word the arm cannot reach. It has never
been swept against the criteria that closed the store gate.
