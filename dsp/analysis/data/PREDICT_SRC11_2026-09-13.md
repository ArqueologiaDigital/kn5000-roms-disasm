# PRE-REGISTRATION — `SRC 0x11`, swept over its three readings against the anchored cells

Written **before** the run. 2026-09-13.

## The target
`SRC 0x11` is the queue's next entry: **54 sole / 77 occurrences over 29 images**, including **5 in
the resident kernel** and 2 in the output stage — so it is on every program's path. The device
already carries all three readings, selected by the SPEC mask:

| arm | mask | reading |
|---|---|---|
| **A** (shipped) | `b910e446a39b440f` | bit 14 set → `acc_to_datum(cur_unit ? accb : acc)` — the CURRENT unit's accumulator |
| **B** | `b910e446a39b040f` | bit 14 clear, bit 1 set → `acc_to_datum(accb)` — always unit 1's accumulator |
| **C** | `b910e446a39b040d` | both clear → `mem[ptr]` |

`§27` shipped the ACCB family; `§113` proposed `mem[ptr]` and it has sat off since, and `§97` showed
this session that the one test ever run on it was aimed at a word the arm cannot reach. It has never
been swept against the criteria that closed the store gate.

## Predictions

| | prediction |
|---|---|
| **J1** | each arm fires — the kernel carries 5 `SRC 0x11` words, so the code runs in every frame |
| **J2** | ⚠ CONTROL THAT CAN FAIL: at least one arm must MOVE a census. If all three are identical the criteria are blind to this code and nothing below is evidence — the §107 outcome, reported as such |
| **J3** ★ | REFUTATION: any arm that collapses the per-unit hand-off cell `0x05` from its live ±2.9 M signal to a frozen constant is out — that is the cell `§76` promoted `SRC0B2` on across 8 programs |
| **J4** ★ | REFUTATION: any arm that rails or churns the **VOLUME** cell `0x06`, or kills the LFO phase cell `07`, is out — the two criteria that eliminated four store-gate rivals |
| **J5** | if exactly one survives J3 and J4, that is the reading, and it must then pass the 10-program hand-off regression before anything is promoted |

⛔ A single surviving arm would decide the SOURCE. It would not decide what the other 23 words in
the population need (`ACT` codes, classes) — the leverage table's "unblocks 54" is the count of
words refused for this axis ALONE.

| arm | reading | hand-off `0x05` | VOLUME `0x06` | LFO `07` |

**J1 ✔**, **J2 ✔** (something does move — see below), **J3 ✗ no refutation**, **J4 ✗ no
refutation**, **J5 n/a**. All three readings survive both criteria.

### ★ And the diff localises the blindness precisely
```
   §176 D-RAM CENSUS   IDENTICAL      0 of 12 cells differ
   §228 LFO RISE       IDENTICAL
   §162 class-6 sites  IDENTICAL
   §175 PER-SITE       DIFFER (3 distinct)   <- the operand L and the product P DO move
   D-RAM WRITES        DIFFER (3 distinct)
```

⇒ the three readings feed **different operands into the multiplier** — `§175` shows `L` moving from
`0..8388607` to `0..7474246` and `P`'s ceiling with it — and **the resulting D-RAM state is
bit-identical, cell for cell.** The difference is absorbed before anything is stored.

★★ That is why the store-gate criteria cannot decide this axis: the hand-off cell, the VOLUME cell
and the LFO phase are all **D-RAM cells**, and no D-RAM cell distinguishes the readings. The gate
was decidable because it changed the accumulator wholesale; a SOURCE swap changes a multiplicand
that the datapath then absorbs.

### What the next pass needs, named
An instrument that sees **`L` and `P` at the `SRC 0x11` sites** — `§175` already reports both — and
a program where the multiplicand at such a word is known from the ROM. That is the same shape as
SINGLE DELAY's lag-1001 product, applied to an operand rather than to an output.
