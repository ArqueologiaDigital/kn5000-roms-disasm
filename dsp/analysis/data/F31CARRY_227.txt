=== 5. IS `P_SHIFT = 7' Q-CONSISTENT?  THE SOURCE'S OWN ANSWER ===
   upd6383.h, verbatim:
     //
     // THE FIXED POINT (notes/dsp-alu-biquad.md sect. 5).  What is FORCED is
     // only the TOTAL: a coefficient is scaled by 2^22 (Q1.22 -- MEASURED from
     // the firmware's own scale constants) while a datum is Q0.23, so the
     // product must be brought back down by 22 bits somewhere between the
     // multiplier and the memory.  WHERE the 22 is split between the multiplier
     // output and the accumulator read is NOT determined -- every split from 2
     // to 12 gives numerically identical results on all eleven ROM coefficient
     // banks.  6 is chosen because it keeps the whole 48-bit product inside the
     // 44-bit ALU with room for the five-term sum, which is the only physical
     // consideration that discriminates at all.
     int P_SHIFT   = 6;
     int ACC_SHIFT = 16;
     u32 m_pshift_mode = 0;

   ⇒ THE TOTAL 22 IS FORCED AND MEASURED: coefficients are **Q1.22**, data Q0.23.
     P as a datum is (coef * L) >> (P_SHIFT + ACC_SHIFT) = >> 22, WHICHEVER split.
     A Q0.23 coefficient would want 23; a Q1.22 one wants 22.  22 SHIPS.
     ⇒ "P_SHIFT = 7 is the Q-consistent value" is FALSE unless the tie is broken,
       and breaking it contradicts the MEASURED Q1.22 coefficient scale.

   The three ladder coefficients read as Q1.22 (value / 2**22):
     C[0x9B] = 0x4CCCCC =  +5033164  ->  Q1.22 +1.200000   Q0.23 +0.600000
     C[0x9C] = 0x400000 =  +4194304  ->  Q1.22 +1.000000   Q0.23 +0.500000
     C[0x9D] = 0x400000 =  +4194304  ->  Q1.22 +1.000000   Q0.23 +0.500000
   ⇒ 1.2 / 1.0 / 1.0 exactly, in Q1.22.  Round coefficients, not noise.

   Is a TIED split even observable?  P as a datum, both ways, on these operands:
     C[0x9B]^2 : split 6/16 -> 6039795   split 7/15 -> 6039795   IDENTICAL
     C[0x9C]^2 : split 6/16 -> 4194304   split 7/15 -> 4194304   IDENTICAL
   ⇒ single-term identity is exact (floor division by 2**m then 2**n == by 2**(m+n)).
     A MULTI-TERM sum can differ by 1 LSB because each product truncates separately,
     so the arm is NOT provably bit-identical -- it was predicted to be UNMOVED at the
     FS scale, which is a falsifiable prediction, and §227 built and ran it:
