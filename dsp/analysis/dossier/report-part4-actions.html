8. Recommended actions, ranked

Separated by who can carry them out, which is the distinction that matters most: the autonomous system has been unable to act on category (b) at all.

8.1 What the autonomous agents can do alone

Action 1 — Decide the current blocker

The preamble's saturating arithmetic, with one named untested reading, bisected so that the two candidate changes are graded separately. Cost: one to two build passes; falsifiers already written. Kill condition: if the saturation rate does not move and the site stays at 1.720 × full scale with a non-zero fired count, the reading is not the defect and the rail is elsewhere among the six sites.

Action 2 — Fix a sample-rate error affecting everything DONE

The emulator ran the DSP's frame clock at 48,000 Hz, because the routine advancing it was driven from the tone generator's audio stream. The chip's actual rate is 44,100 Hz. Proven with no run at all: every archived experiment reports 1,440,001 frames on a thirty-second vehicle, which is exactly 30 × 48,000. Every emulated delay, reverb and oscillator was 8.844 % fast.

The review's supporting evidence for this was wrong, and so was the brief derived from it. Both claimed the project had already measured the discrepancy and filed it as an unexplained residual. It had not: that figure was derived from the oscillator's increment, never measured. The only instrument capable of measuring it prints 0.5000 Hz and always has — its denominator includes the 264,001 frames before the program is uploaded, during which the ramp is frozen, and its numerator truncates a partial wrap.

The implementing pass also found that the kill condition it had been given could not fail: that census computes frequency as wraps/frames × declared rate, and the ratio is rate-invariant, so editing the declaration alone would have moved the number to the target with nothing measured. It replaced the criterion before building.

Result, measured with a purpose-built instrument:

  0.652313 Hz  ->  0.599313 Hz
  step 114..114 CONSTANT, period 73,584.3 frames  --  BIT-IDENTICAL between arms
  frames per second   47,985.602  ->  44,086.742
  frames run  1,440,001  ->  1,323,000  =  30 x 44,100 exactly

The invariance is the proof: the oscillator's step and period are unchanged to the bit, so only the clock moved. The tone generator, which is audible and shipping, was regression-tested three ways and returned byte-identical output with a positive control that could have failed. A consequence worth noting for anyone reading older material: every delay-age figure in milliseconds in every previous log is 8.84 % high.

Action 3 — Run the cross-unit experiment on the largest undecoded field

Select GATED REVERB into unit 0 with a reverb preset resident in unit 1, making both halves of a minimal pair co-resident in one frame (section 7.1). Cost: one read-only pass to choose the discriminator, then two build arms. Kill condition: if the two images differ in too many other fields to isolate the pair, abort before building — and restate the field's closure honestly as "no clean discriminator" rather than "no co-resident pair".

Action 5 — Repair the bookkeeping

Generate the shipped-fix list from the source's own declarations rather than maintaining it by hand; add a check that fails when a handover document quotes a configuration value that disagrees with the source; complete the rules index and either define rule 20 or delete it; and extend the index generator to sweep the notes directory it currently ignores, so that results like the negative cross-model comparison cannot go missing again. Cost: two to three agent-hours, no emulator runs.

Action 6 — Bundle three cheap items into one pass

The single-image minimal pair from section 7.1; loud diagnostic banners for six instruction sources that currently inject 10,702,080 silent zeros per run without saying so; and one log line per program upload naming its address, size and hash, so that "how many programs have ever executed" stops being an inference. Kill condition: if the minimal pair measures identical on every channel, the no-operation reading is confirmed — still a result, and the first field decision in five days.

8.2 What needs Felipe and the physical instrument

This is the only channel with zero data after nine days. There is no recording of the real KN5000 anywhere in the three repositories — no .wav, .flac, .aif or .mp3. The request has been filed since 22 July and has not been touched since.

A measured reverb decay time yields the per-pass loop gain numerically — the one quantity the project has guessed wrong three times.

Action 4 — One thirty-minute sitting, with a prerequisite

The agents must first publish a table mapping each front-panel effect name to its algorithm slot, to which chip handles it, and to the program image's hash. Without it a recording may capture the wrong chip: "ROOM" names both an effect on this DSP and a master reverb on a second processor in the same machine. The raw material for the table already exists.

Then, in one sitting:

  1. Take A. Select CONCERT REVERB 1 at factory depth, master and panel reverb at minimum, everything else silent. Play one short percussive note and let it ring for at least six seconds. The dry note must be visible in the recording — this is the positive control.
  2. Take B (mandatory). Identical, but with the DSP effect switched off. Same gain, same session. If A and B are not audibly different, the wrong chip or the wrong output was captured and the session is void.
  3. Take C. Change only the effect name to SLOW ATTACKER and play the same note. (The project predicts this effect does nothing at all — it ships a program byte-identical to "no operation".)
  4. Photographs: the marking on crystal X301, and the marking on IC311.
  5. One part number: the DRAM chip next to IC311.

Line output preferred, 24-bit, 44.1 or 48 kHz. A phone recording is better than nothing. The agents will commit their predicted early-reflection times and decay band to version control before you record, so the comparison is a genuine test rather than a fitting exercise.

8.3 What needs external resources

  • A DRAM datasheet for the part beside the chip. Minutes of effort; no search has ever been run. It settles the delay memory's real organisation and upgrades a load-bearing inference to a measurement. The cheapest external item available.
  • A firmware dump from a Pioneer CDJ-500, which uses the same DSP. This is the only route to six instruction sources that occur exactly once each in the KN5000 corpus — none of them reachable by any method internal to this machine. Community-dependent, latency in weeks: dispatch it and then ignore it, because it can never be on the critical path.
  • Patent searches are largely exhausted — the part number returns nothing. One residual lead is worth an hour and no more. The review explicitly warns against re-attempting a cross-decode from a related part number: its word length differs and the divergence is verified.

9. What the review rejected

The adversarial stage discarded a number of proposals, including several the project itself had been entertaining. These are listed because a review that only adds recommendations is less useful than one that also removes them.

  • "The silence metric is manufactured by a fallback branch in the code." Refuted at source: the presentation routine reads the accumulator, not the bus that the fallback feeds.
  • "Retire the silence measurement as the goal metric." It already is not one — the project's own ledger directs grading onto the per-instruction saturation count instead.
  • Seeding a coefficient pointer at frame start. Refuted 26 minutes after the commit it was built on; the pointer is already seeded, and the proposed change is 1.6 × worse with a different effect loaded.
  • A proposed coverage metric in which 26 of its 32 denominator slots can never score — it would read zero whether the project were healthy or dead. The review notes this is exactly the "criterion that cannot fail" failure the project has caught thirteen times.
  • Using the sibling instrument's working DSP as a semantic oracle — already run on 22 July, negative.
  • A second concurrent emulator lane, and implementing one of the unread instruction sources — both refused on the project's own existing evidence.

10. Conclusion

The review's own one-sentence answer:

"The method is better than the field standard and the lane's current target is correct — but the project has stopped decoding while telling itself it is decoding, has left a 4 %-of-everything clock error and three one-selection experiments on the table, and has never once asked the instrument in your living room a question."

The discipline is not the problem, and should not be relaxed: it caught three false "the chip produces audio" claims, one of which passed every test the project owned at the time. The problem is allocation. Four of the six recommended actions cost a single pass each and have been available for days; the fifth is bookkeeping; and the sixth needs thirty minutes with a microphone.
