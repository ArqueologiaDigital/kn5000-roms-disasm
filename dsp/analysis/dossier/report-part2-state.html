3. What the work has established

This section states the technical position as of 31 July 2026, independently of any judgement about whether that position represents good progress. Every figure here was measured by the project and is cited in its technical register.

3.1 The signal path, traced end to end

The chip processes each audio frame by running a fixed sequence of 285 instruction slots: a kernel, two effect bodies (one per effect unit), and a final block that presents the result to the outputs. Where the audio is lost along that path is now known precisely.

StageFindingEvidence
Input reaches the chip Audio arrives and is deposited into the first unit's input cell by two instructions. MEASURED input-dependent values observed
Input is destroyed before use Two later instructions overwrite that cell before the effect body is called. The body then reads a constant, and afterwards zero. MEASURED slot-by-slot residency census
Second unit never receives input Its input cell has no writer at all. The equivalent cell in the first unit has six. MEASURED two instruments, four experimental arms
Second unit's accumulator dies One instruction loads that empty cell into the accumulator, killing 128 of the unit's 133 slots. All twelve reverb programs run in this unit. FORCED from the instruction order
The only link to the output Exactly one instruction carries a body result to the final block. It runs 540,000 times out of 540,000 and carries zero every time. MEASURED provenance-tagged census
The output block is disconnected Its operand census is byte-identical between an experiment where signal flows through the bodies and one where it does not — every route, index, range and provenance column, all 18 rows. MEASURED differential census

The significance of the last row. The output block was long assumed to be starved — correctly wired, waiting for input that never came. An identical census across an arm where the effect bodies demonstrably carry live audio proves something stronger and worse: its operands do not come from the signal path at all. It is not waiting for input; it is not connected to one.

3.2 A defect that is visible without any signal at all

A census of arithmetic before the saturation clamp is applied — a distinction that matters, because after clamping a saturated value is indistinguishable from a legitimate full-scale one — found the following in the shipped emulator:

  input exactly zero    9,884,596 of 186,394,560 conversions saturate    5.303 %
  input loud                                                             5.298 %

The emulated chip clips more often with no input than with input. Seven instruction sites saturate on 100 % of silent frames. This is not an artefact of a test apparatus: it is present in the default build, and a second, narrower apparatus deleting one quarter as much reproduces the effect whole.

3.3 What has been fixed

Eight gates, across eleven register sections, have changed the emulator's behaviour and been kept. Every one belongs to a single category: a claim already proven elsewhere in the project's own notes or source which the emulator simply failed to implement. Representative examples:

That figure was itself a bookkeeping casualty, and is stated here with its unit for a reason. The project's own documents give the count as five, seven, "7 of 7", eight and nine in five different places, with no enumerated list anywhere. An audit commissioned during this review found the cause: no published figure states what it is counting. One section ships two gates; two other sections share one. Counted as gates the answer is eight; counted as sections, eleven. Every previously published figure — including one in an earlier draft of this report — was wrong for both units. The list is now generated from the source's own declarations rather than maintained by hand.

  • A host communication packet decoded with its least significant bit dropped, so that a third of every parameter in the machine was one unit low. Two notes contained the correct formula. After the fix, the residual error was exactly 1/√2 — pure rounding.
  • An index that was never reset between the two effect units, so the second unit read memory nobody had written. Delay lines had, measurably, no length at all before this; afterwards they had the lengths the ROM designs for them, matching the stored values exactly.
  • A modulo operation that added its modulus instead of applying it — proven by a difference of exactly 0x7FFFFF at both endpoints, which is the constant the emulator's own source annotation names "wrap".
  • A no-operation guard testing three of the four instruction fields, swallowing 103 instructions the disassembler and the generated listings both handled correctly. The emulator core was the only one of three implementations that got it wrong.

The pattern worth noticing: not one of these fixes originated in a hypothesis the project invented. Every one was a correction of the emulator against knowledge the project had already written down. Whether this is a strength of the method or a limitation of it is one of the questions this review was commissioned to answer.

3.4 The measuring apparatus, audited

Because the conclusions rest entirely on instrumentation the project wrote itself, that instrumentation was swept: 203 diagnostic instruments across 266 print sites. The audit found defects in five classes, including counters that report visits rather than the events they are named for, a column header listing thirteen names over twelve values, and — universally — 48 of 48 sampling instruments that arm once and never reset, pooling measurements across program changes.

A follow-up triage then quantified the damage: of 2,163 live measurement-bearing conclusions across 96 files, the confirmed defects touch fourteen, and none of them is an open load-bearing claim. Both defects proved to be bounded to specific date ranges, and the central "the chip is silent" measurement was confirmed sound and independently corroborated by a second instrument.

A near miss worth recording. The instrument that reports silence stores its running minimum in a sentinel value. A sibling instrument's sentinel is reset by the device's reset routine. Had the silence instrument's been treated the same way, its minimum would have been pinned at zero permanently and every "the chip is silent" statement in this project would have been an artefact of its own reset code. It is not — and both defects it does carry bias it toward reporting a non-zero result, so they cannot manufacture the null.

3.5 What remains undecoded

Several instruction fields have resisted decoding, and it is important to distinguish two very different reasons:

Undecidable by the method used
The primary technique is the minimal pair — find two programs identical except for one bit, and compare. One field has five such pairs but no single loaded program ever contains both halves of any pair, so no experiment of this shape can ever exhibit a difference. This is a limit of the method, not of the field.
Closed on evidence
Other candidate readings have been positively refuted — for instance an entire alternate instruction encoding whose four routes to decidability were each closed, and a proposed operand-latch mechanism refuted by a two-sided experiment in which one arm produced a census byte-identical to its control.

A search space that was once a 64-bit configuration mask of candidate behaviours is now exhausted: 61 of its 64 bits are referenced by the code, and the three that are not are set by default. New hypotheses now require new mechanisms rather than new combinations.
