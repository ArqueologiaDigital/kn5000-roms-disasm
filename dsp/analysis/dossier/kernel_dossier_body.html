Part K — The shared kernel

Every effect on the SX-KN5000 is a guest. The uPD6383GF runs 285 microcode slots per frame, and 83 of them are the same words in every preset ever selected — a 60-word header and a 23-word output stage, both literal canned images in Sub CPU ROM, uploaded once and never recomputed. This part of the dossier is about those 83 words. It matters for one specific reason: eleven of the shipped emulator's twelve saturation sites — and 99.9996 % of its clips — are inside the header. The audio is destroyed there before any effect sees it, and the constants it is destroyed with are read out of the reverb's own parameter bank, which means the overflow changes when the user changes reverb preset.

Read this before any number below. Everything measured here is measured on the MAME model upd6383.cpp, not on hardware. A grade of MEASURED means "measured in the model"; where the model and the chip could differ that is said explicitly. All frame counts and clip counts come from dsp/analysis/data/B_44100_228.log.gz — the shipped default arm on the 44 100 Hz frame clock adopted in §228. Pre-§228 logs ran at 48 000 Hz; their frame counts are 8.844 % high and must be re-derived, never quoted. Two figures in the brief that generated this document are pre-§228 counts; see the errata.

K1. What the kernel is, and what actually runs

The kernel is two op-3 uC-IF records in the Sub CPU ROM, both literals — nothing in either is computed by the firmware (FORCED, proven by construction):

0x01E496 — the header, 60 words, loaded at I-RAM 0
shipped by EFF_WriteHeader as one cmd 0x01 record to I-RAM word address 0x0000.
0x01E63C — the output stage, 23 words, loaded at I-RAM 60
shipped by DSP_AlgorithmChange. Exactly two of its words are ever rewritten by the host — I-RAM 64 and 71, the per-unit link/disconnect call vectors.

The 60-word header does not run as one block. It is cut in two by the unit-0 CALL at I-RAM 49, so the frame's slot order is:

Two corrections to the framing this document was commissioned with. (i) Kernel A is I-RAM 0..49, not 0..59. I-RAM 50..59 is the same canned image but it is kernel B, and it runs 70 slots later. (ii) The epilogue image is I-RAM 60..82 (23 words) but only 60..81 execute as slots. I-RAM 82 is C00.A.47.407, the frame-wait terminator whose 13-bit immediate encodes its own address (82×32 + 7); it ends the frame rather than occupying one of the 285. Both are arithmetic facts, not judgement calls: any other split does not sum to 285.

What runs regardless of the effect selection? All 83 kernel + epilogue words. The call vectors at I-RAM 64 / 71 take exactly four values — 84 and 42 for unit 0, 200 and 50 for unit 1. 84 and 200 are the load addresses of every unit-0 and unit-1 body across all 91 IC311 streams; 42 and 50 are the first words of that unit's own header setup block, so an unlinked unit does not skip the header — it re-enters it, runs the setup block and returns. FORCED.

Checked, because the brief asked: I-RAM[154..199] is never uploaded — but that 46-slot hole is body 0's tail, between CHORUS's 70-word image and body 1's load address. It does not touch the kernel (0..59) or the epilogue (60..82). MEASURED — upload ledger, 12 runs, 8 distinct images, matching the offline corpus 4 of 4 (KERNEL 60, EPILOGUE 23, CHORUS 84/70, ROOM REVERB 1 200/133).

K3.1 The ladder, word by word

The chip's product register is one word deep: the accumulator update at slot N consumes the product formed at slot N−1. That is visible directly in the frame trace's P column and it is what makes the ladder legible. Fixed point: P = (coef × L) >> P_SHIFT with P_SHIFT = 6 and ACC_SHIFT = 16; the datum is acc_to_datum(acc) = acc >> ACC_SHIFT then clamped to ±(223−1). The Q-consistent total is 22, coefficients being Q1.22 and data Q0.23 — P_SHIFT itself is 6, and 6 + 16 = 22. FORCED (the core's own header) and MEASURED (a 7/15 split is bit-identical over 269 279 999 conversions; a 7/16 split breaks the m_rf[0x8D] = 0x009B26 calibration).

K4. ★★ The kernel ↔ reverb link

The header's coefficient cursor is seeded by an instruction, not by a frame-start assignment. The corpus contains exactly three ldptr words — iw42 → 0x70, iw50 → 0x50, iw69 → 0x90 — and iw69 is in the epilogue, which runs last, and the epilogue contains zero cursor-advancing words. So the cursor at the next frame's w0 is 0x90 exactly, every frame. FORCED (source + corpus), and MEASURED live: the frame trace's cursor column reads 0xB1 at slot 263 (left behind by body 1) and 0x90 at slot 284.

The header block proper then walks 20 cells, base+0x00 .. base+0x13, before iw42 re-aims the cursor:

  w5:+00  w6:+01  w7:+02  w10:+03  w14:+04  w16:+05  w17:+06  w18:+07  w20:+08  w21:+09
  w23:+0A  w30:+0B  w32:+0C  w33:+0D  w34:+0E  w35:+0F  w36:+10  w37:+11  w39:+12  w41:+13
  ---- w42  ldptr #$70  RE-AIMS THE CURSOR ----     w45:+14 (reads 0x70)

With base = 0x90 the ladder's cells are 0x9B / 0x9C / 0x9D, which is exactly where the live measurement puts them. FORCED.

And C-RAM[0x90..0xB4] is unit 1's per-algorithm parameter bank — the reverb's. Changing the reverb preset from CONCERT REVERB 1 (the cold-boot default) to ROOM REVERB 1 rewrites 23 cells, every one of them inside 0x90..0xB4 and nothing else in the 256-cell C-RAM:

   CONCERT REVERB 1   0x9B/0x9C/0x9D = 4CCCCC / 400000 / 400000   ->  iw33 = +1.720 FS   CLIPS
   ROOM    REVERB 1   0x9B/0x9C/0x9D = 400000 / 333333 / 400000   ->  iw33 = +1.320 FS   CLIPS
   in Q1.22 these read as reverb gains: 1.200/1.000/1.000  and  1.000/0.800/1.000

MEASURED, and proof-grade because of its control: an independent 45 s panel run (boot → SOUND → REVERB page → 40 DOWN → 4 UP) landing on CONCERT REVERB 1 reproduces the archived 2026-07-22 cold-boot capture on all 256 C-RAM cells, 0 differ — so the replayer is faithful, the navigation perturbs nothing, and the cold-boot default reverb is CONCERT REVERB 1.

⇒ The shared, effect-independent, canned kernel computes with the user's reverb coefficients, and its overflow is preset-dependent. This is the most interesting structural fact the kernel has. It is also a reproduced fact, not merely a quoted one: running the ladder offline from the ROM words and the ROOM REVERB 1 bank gives 1.320 × FS to three decimals, which is what fixes the term attribution in K3.1 — the rival assignment predicts 1.400.

What this does and does not license. It does not mean the base is wrong. Three readings remain separable and no falsifier distinguishes them yet: (1) the base is seeded elsewhere and row 25's ldptr → cursor rule is wrong; (2) the base is right and a canned header legitimately reads the reverb's gains, since it runs immediately before the reverb's own CALL; (3) the cursor-advance map is wrong. ⛔ Aiming the header at 0x00 is refuted: that is unit 0's bank (PARAMETRIC EQ rewrites all 20 cells), and the same ladder run there with PEQ loaded reaches +2.733 FS — 1.6× worse. MEASURED. ⚠ kernel.dsm's printed "base 0x00 MEASURED" is a generator default, not a measurement of the header.

The family predicate is addressing mode 1 with the hi12 format-escape bit, exceptionless over the corpus; addr8 bit 6 is the direction field. K6. The LFO

Attribution first: the LFO is not a kernel object. The phase ramp lives in body 0 — words iw89, iw91, iw92, iw94, i.e. CHORUS — and its two constants come from unit 0's parameter bank at C-RAM[0x00] and C-RAM[0x01], not from the header's bank at 0x90. It is in this dossier because the kernel-focused instruments found it and because it anchors the fixed-point regime, not because the kernel owns it.

   C-RAM[0x00] = 0x000072 = 114        the RATE      -- iw89 puts it on the bus:  acc = 114 << 16
   C-RAM[0x01] = 0x7FFFFF = 8 388 607  the WRAP      -- iw91's SRC-0x08 operand; upd6383.cpp's own
                                                       C-RAM annotation calls this cell "wrap"
   D-RAM[0x07]  the PHASE       ramp, quiet [4 .. 8 388 594], 1 080 450 writes, step 114..114 CONSTANT
   D-RAM[0x10]  the MODULATION  published by iw92

The defect and its fix. iw91 is the wrap word. The model applied ACTION 0x00 to it literally — i.e. it added the operand to the accumulator — so iw92 published clamp(phase + INC + 0x7FFFFF) and D-RAM 0x10 was a full-scale DC on every frame while the phase itself ramped correctly. The difference between the two slots was exactly 8 388 607 = 0x7FFFFF at both endpoints of both buckets — the wrap constant itself. The fix applies the operand as a modulus at the adder only: acc ← (datum(acc) & L) << ACC_SHIFT. It is now the default (UPD6383_LFOWRAP = 1, 1 081 332 wrap steps per run taking the modulus path, one distinct slot) and the two-sided OFF control is kept. MEASURED: after the flip, iw94's cell reads 1 006 898, 1 007 012, … 1 007 696 on eight consecutive frames — a +114/frame ramp. The chorus LFO reaches its published cell for the first time.

The rate. The step is 114 per frame and the phase is 23-bit, so the period is 223 / 114 = 73 584.3 frames and

   f = 114 x 44 100 / 2^23 = 5 027 400 / 8 388 608 = 0.599313 Hz   (period 1.66858 s)

Do not grade a clock change on this number. The census's Hz is wraps/frames × DECLARED rate and wraps/frames is rate-invariant, so changing the declaration alone moves it with nothing measured — a criterion that cannot fail is not a pass. The clock is graded instead on frames per emulated second against the machine's own clock (44 086.742 against 44 100 declared, relative error 0.000301) and on the step and period staying invariant, which they do. ⚠ The older wrap census that printed 0.5000 Hz is superseded and biased low two ways. Fs = 44 100 has four proofs, all inside the ROM; the "33.8688 MHz = 768 × 44 100" crystal argument is INFERRED only — the 1996 scan prints 36.8688 MHz, which divides to neither rate.

K10. The full per-word listing

All 83 words that run in every frame of every preset: the 60-word header (kernel A I-RAM 0..49 + kernel B I-RAM 50..59) and the 23-word output stage (I-RAM 60..82). Raw words are the ROM's own bytes, 36 bits right-aligned in 5. Rows shaded and marked und are UNDECODED — nothing about the word's job is established, and for 25 of them nothing executes at all.

Field key. hi12 = bits 35..24, a horizontal microword of independent enable bits, not an opcode; class4 = 23..20; addr8 = 19..12; lo12 = 11..0. In the C-format family (hi12[11:8] == 0xC) bits 24..12 are one 13-bit immediate reaching into hi12 bit 0, so class4 / addr8 do not exist there and print as –. SRC = lo12[10:6], ACT = lo12[4:0] — the operand routing, always taken from the disassembler's own accessors and never by eye, since 11 distinct lo12 values occur on both class-1 delay words and class-2 words. f31 = hi12[3:1], the accumulator operation (0 = load P, 1 = accumulate, 2 = hold); f98 = hi12[9:8], an arity field of unestablished meaning. Flags: ESC = format escape (bit 11), END = end of block (bit 10, only when ESC is clear), ST = write accumulator to mem[ptr] (bit 4), cur+ = advances the coefficient cursor (class4 == 0xA, not C-format), p±n = signed pointer post-increment by addr8 (class4 & 7 == 2). C-RAM = the absolute cell this word's multiply consumes, from the frame-start base 0x90 and the in-block ldptrs.

This part was produced read-only: no repo file was edited, no build was run, no emulator was launched.
