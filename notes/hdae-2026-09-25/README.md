# Lane `hdae`, semantic push 2026-09-25 -- tools and evidence

Every number this lane quotes in a commit message or source header was produced
by one of the scripts below.  Each answers one question; run from the repo root
after any build of `rebuilt_ROMs/hd-ae5000_v2_06i.llvm.rom` (the generated image
blobs must exist).

| script | question it answers | command |
|---|---|---|
| `scripts/analysis/hdae5000_line_map.py` | which hdae5000 source line emits the byte at address X (and at what address does line N assemble)? The mirror it links is asserted byte-identical to the dump, so the map describes the tree it was run on. | `python3 scripts/analysis/hdae5000_line_map.py 0x2974DD 0x297500` or `--dump OUT.tsv` |
| `scripts/converters/symbolize_abs24_cc_branches.py` | converts the numeric `jp/call cc, (N:24)` operands that `symbolize_numeric_branches.py` skips ("skip_conditional_abs"; its regex does not accept the `(N:24)` spelling). Guards: ROM encoding F2 <addr24> Dx/Ex matches, unidasm agrees, target is the first byte of an instruction line. Dry run prints the counts; `--apply` rewrites and re-links through the line-map tool (refuses unless byte-identical). | `python3 scripts/converters/symbolize_abs24_cc_branches.py [--apply]` |
| `scripts/renaming/sed_to_rename_map.py` | the `old=new` map a `scripts/renaming/*.sed` performs, for `assert_comments_preserved.py --rename-map` | `python3 scripts/renaming/sed_to_rename_map.py X.sed > X.map` |
| `scripts/generators/gen_hdae5000_ui_pool.py` | writes the 769 typed records of the UI object descriptor pool (0x29DC12-0x2A5D2B) and the symbolic `HDAE5000_UiObject_PtrTable`; refuses unless its byte model of the generated text equals the ROM, and the layout facts it relies on still hold. Idempotent on its own output. | `python3 scripts/generators/gen_hdae5000_ui_pool.py [--write]` |
| `scripts/converters/hdae5000_label_langtext.py` | who reads HDAE5000_Multilingual_Messages, and how? Asserts from the ROM + source: the 80-entry u16 switch table at 0x2E5AE0 of HDAE5000_AcLanguageText1Proc, 78 case targets all on instruction starts, and that the cases push all 232 strings of the block (0 unreferenced). `--apply` did the labelling (already applied; re-running it would double-insert). | `python3 scripts/converters/hdae5000_label_langtext.py` |
| `scripts/analysis/hdae5000_reachability.py` | which HD-AE5000 code can never execute? Conservative closure from the header entry block, `.long` pointers (LE32) anywhere in the data part, and labels named by the data files, under fall-through + every label/numeric operand; switch-table cases count only through their table's label. Prints the unreachable ranges (`--labels`: LIVE/DEAD per label; `--tsv`: per line). A conditional `ret cc` falls through (fixed 2026-09-25: it had been taken as terminal, which marked 437 B of loop bodies dead; the tree then measured 5,868 B unreachable in 118 ranges instead of 6,305 B / 137). | `python3 scripts/analysis/hdae5000_reachability.py [--labels]` |
| `scripts/converters/hdae5000_switch_tables.py` | the compiled `switch` jump tables: 51 sites of `[sub/dec] / cp 0 / cp M / add xwa,xwa / add xwa,TABLE / ld wa,(xwa) / lda xix,BASE / jp T,XIX+WA`, each with its M+1 u16 offsets in the .rodata at 0x2E1C82.. that earlier passes typed as text. Asserts every target is an instruction start and every table is emitted by whole lines (splitting a straddling line into typed fragments); `--apply` did the conversion (already applied). | `python3 scripts/converters/hdae5000_switch_tables.py [-v]` |
| `scripts/generators/gen_hdae5000_rodata.py` | what are the bytes of the C program's .rodata (0x2E1C82-0x2E3703), object by object, and which routines read each? Objects start at every address the code names (lda / ld # / ld (mem) / add # operands, `pushw 0x002e` + low-half pairs) or that a string-pointer table in the block points at; typed as `.asciz`/`.long <label>`/UI object ids/templates/floats, switch tables kept; prints the object list, `--write` rewrites (already applied; re-running regenerates the same text from a tree that still has the old block). `--block2` does the same for the lyrics module's .rodata 0x2E5B80-0x2E5DCD (47 objects; applied in 16a6f80e). | `python3 scripts/generators/gen_hdae5000_rodata.py [--block2] [--write]` |
| `scripts/converters/hdae5000_symbolize_rodata_refs.py` | turns every code operand that equals a .rodata label's address into that label (321 sites in the first block: 134 lda, 66 ld, 121 pushed low halves annotated "; low half of <label>"; a second run over both blocks added the lyrics block and the decimal `pushw` spelling, and appends "-- high half of <label>" where the high half already carried a different comment); refuses addresses inside an object. `--apply` done. | `python3 scripts/converters/hdae5000_symbolize_rodata_refs.py [--apply]` |
| `scripts/converters/hdae5000_symbolize_ui_objects.py` | which UI object does each `0x007Fnnnn` id name? Generates `.equ HDAE5000_OBJ_<name>` for the 178 objects HDAE5000_UiObjectName_PtrTable names and replaces the 390 id immediates/.long values (all of them name a named object). `--apply` done. | `python3 scripts/converters/hdae5000_symbolize_ui_objects.py [--apply]` |
| `scripts/converters/hdae5000_symbolize_ram.py` | names 43 RAM variables whose role the code shows (each `.equ` carries its evidence) and rewrites the 1,827 operands equal to one of them (956 of them the main-CPU workspace pointer 0x23A1A2). A second run added 7 lyrics-player variables (74 operands), a third the frame handler's 8 (16 operands), a fourth the floppy lyric list's 5 (36 operands); re-running only appends names missing from the block. `--apply` done. | `python3 scripts/converters/hdae5000_symbolize_ram.py [--apply]` |
| `scripts/converters/hdae5000_symbolize_fn_tables.py` | which main-CPU function does each `(workspace + 0x0E0A / 0x0E88)[off]` call reach? The workspace is the object table 0x027ED2 (RegisterObjectTable: 14-byte records, data pointer at +10), so +0x0E0A / +0x0E88 are the data pointers of tables 0x100 (InitializeRoot: FunctionProc table 0xEAFA6E) and 0x109 (InitializeHama: 0xE1F0EC).  For each of the 100 offsets used at 953 sites it reads the function pointer and the NAME the firmware files under the same index in the companion name table (0x400 WidgetName_InitPtrTable, 0x409 Hama_ModeParam_Table) from `original_ROMs/kn5000_v10_program.rom`, and compares with the v10 build's label there (99 agree; offset 0x084 is `UpdateScreen`, which the v10 build labels `LcdOff_Epilogue`).  Writes `.equ RootFn_<name>` / `HamaFn_<name>` / `WS_RootFnTable` / `WS_HamaFnTable` and rewrites the operands. `--apply` done. | `python3 scripts/converters/hdae5000_symbolize_fn_tables.py [--apply]` |
| `scripts/renaming/rename_hdae5000_*.sed` | the label renames of this lane, one file per commit topic (libc, pport, ata, fat, songio, screens, pport_cmds, uimisc, lyrics_events, fdlyrics); each rule's evidence is in the renamed routine's header. `sed_to_rename_map.py` turns one into the map `assert_comments_preserved.py --rename-map` needs. | `sed -i -f scripts/renaming/rename_hdae5000_<topic>.sed hdae5000/*.s` (already applied) |
