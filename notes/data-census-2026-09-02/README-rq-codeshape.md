# rq-codeshape lane outputs — how to regenerate every number

Companion to `notes/lanes/rq-codeshape-2026-09-02.md`, which adjudicates the two
"code misclassified as data" populations of `DATA-CENSUS-2026-09-02.md` §6.

All figures were taken at `tlcs900_backend @ 6f456a19f05b`
(`6f456a19f05bf94696728e89e74a53ed62dc9adf`). Anything below that decodes or
assembles is a property of that build as much as of the bytes — re-derive a
before/after pair with one build, never across a toolchain rebuild.

| script | what question it answers | command |
|---|---|---|
| `scripts/analysis/code_suspect_sites.py` | Which data regions are the target of a control transfer, and **from where**? The census counts 1,089 and discards the list; this enumerates it with every referring site. Reads source text only — no decoder, so no toolchain dependence. | `python3 scripts/analysis/code_suspect_sites.py` and `--refsites` for per-site detail |
| `scripts/analysis/code_suspect_adjudicate.py` | Is each of those transfers real or a phantom? Address guard against the linked image's symbol table, decode from the branch-target alignment, per-instruction round-trip, and the referrer's instruction-run length. | `python3 scripts/analysis/code_suspect_adjudicate.py v7 v9 v10` |
| ” `--null` | **The flag's null.** Not the pure-data images (their zero is pinned by construction) but the 11,179 C-compiled `.incbin` regions inside the same code-bearing images, plus the numeric-transfer confound check. Answer: 0 of 11,179, and 0 of 711 numeric transfers. | `… --null` |
| ” `--randomctl` | **The decode test's null.** Uniformly random bytes at the same lengths: 0.8 % fully clean + round-tripping, 24.2 % endpoint-exact. | `… --randomctl 120 --sizes 8,16,24,32,48,64,96,128,192,256` |
| ” `--blockers` | For the regions that do NOT convert: is the branch target not an instruction start (the phantom shape), or does the decode pass it and hit a backend spelling gap? Names the first blocking form. | `… --blockers` |
| `scripts/analysis/code_shape_shortlist.py` | How much of the 542,405 B "code-shaped label" flag is worth disassembling, ranked with per-region evidence — and how much of it is self-labelled tables. | `python3 scripts/analysis/code_shape_shortlist.py --decode --top 120` |
| `scripts/converters/convert_code_suspect_v7.py` | Convert only the graded regions that pass both evidence gates. | `python3 scripts/converters/convert_code_suspect_v7.py` then `--apply` |

## Prerequisite

    make rebuilt_ROMs/kn5000_v7_program.llvm.rom   # and v9 / v10

The `.llvm.elf` beside each `.rom` is what supplies label addresses. Building it
is also the address guard: the ROM is byte-identical to the dump, so a symbol
address is a fact about the shipped image, not about a cached map.

## Deliberately not committed

`code_suspect_v7.json` / `_v9` / `_v10` and `code_shape_shortlist.json` are
regenerated by the commands above in minutes and drift as other lanes convert.
The recipe is here; the bytes are not.
