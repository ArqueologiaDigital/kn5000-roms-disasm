# Lane w13/census-structs — struct conversions, 2026-09-02

Goal: take the largest structured-record regions that are `.byte` soup with no
field names and give them C structs with **reader-derived** field names, keeping
every ROM byte identical.

## Converted

### 1. `MSP_FACTORY_DEFAULTS` — 5,376 B, all three images
`v{7,9,10}/maincpu/msp_factory_defaults.c` + `.incbin` in the `.s`.
Generator/verifier: `scripts/generators/gen_msp_factory_defaults_c.py`.

Not a table of "MSP parameters".  `Voice_InitBankData` copies it to RAM
0x1E8B00; `Voice_GetSlotAddress` indexes that as `base + (i << 8)`; and
`midi_dispatch_handlers.s` builds a region descriptor of size 0x3900 = 57 × 256.
So it is the factory image of the first 21 blocks of a 57-block linked-list pool
for accompaniment byte streams.

| field | name | the instruction that names it |
|---|---|---|
| +0x00 | `allocated_and_marker` | `bitm 7,(xhl)` (count free), `ormi8 (xix),0x80` (alloc), `andmi8 (xix),0x7f` (free), `cp a,0x87` |
| +0x01 | `prev_block` | `ld (xix+1),de` / `ldw (xix+1),0xffff` |
| +0x03 | `next_block` | `ld hl,(xix+3)` chain walk; `ld wa,(xix+3)` then `stda16 (0x7f10)` + cursor 6 |
| +0x05 | `guard_05` | no reader — named for the offset.  0x87 in all 21 blocks and in `Voice_SlotTemplate` |
| +0x06..+0xFE | `stream[249]` | cursor init `lds wa,6`, wrap test `cp wa,0xff`, byte access `ld (xix+xhl),a` |
| +0xFF | `guard_ff` | no reader — same as +0x05 |

The stream rows are split at **event** boundaries.  The event lengths
(0x90→6, 0x91→8, 0xD1/0xD2/0xD3→3, 0x81/0x83→1) are *not* read off a handler:
they are the unique set under which all twelve chains tile exactly, 558 events,
every chain ending on the 0x83 terminator with nothing but zeros after it.  The
test can fail — any other length set desynchronises within a few events onto a
byte that is not one of the seven opcodes `AccompSeq_SeqParse_Dispatch` tests.
Events straddle six of the eight block joins in the 9-block chain, which is the
direct evidence that the pool is a byte stream and not an array of records.

### 2. The 18-byte sound-parameter descriptor — 951 of 974 records, 17,118 B (v10)
`v10/maincpu/audio/sndparam_records/*.c` + `sndparam_types.h`, nine runs
`.incbin`'d from `extensions/extension_data.s` and one from
`ui_widgets/widget_dispatch.s`.
Generator/verifier: `scripts/generators/gen_sndparam_records_c.py`.

Registered by `SndParam_RegisterAllWidgets` (`audio/sndparam_routines.s:3135`),
which walks 972 pointers from 0xEE01A0, hashes the u32 at +0x00 and stores
{key, pointer}; every `(xwa+N)` in the `SndParam_*` accessors is a read of +N.
Full per-field citations are in `sndparam_types.h`.  Summary: `key` (+0x00),
`bank_index` (+0x04), `bank_offset` (+0x05), `mask` (+0x06), `clamp_min`
(+0x07), `clamp_max` (+0x08), `shift` low nibble (+0x09), `xor_value` (+0x0A),
`aux_index` (+0x0B), and the four bounds-checked accessor indices plus the codec
selector (+0x0C..+0x10), each emitted with the routine name its index selects.

**`unknown_0x11` is the only unnamed field**: no `(X??+0x11)` load exists
anywhere in the 0xFCD200-0xFCF000 accessor region.  0xFF in almost every record,
which is consistent with padding — consistent is not evidence.

Corrections landed with it: the block is 974 records at 0xEDBA44-0xEE0154, not
"956 at 0xEDCAD6-0xEE0010"; the six label prefixes (`ExtPartParam_*`,
`SeqMixParam_*`, `PartParam_*`, `MidiChParam_*`, `VoiceParamEx_*`,
`VoiceCtrlR1_*`) were assigned by address-range bucketing in commits `feda55d9`
and `16f0917a` and mean nothing; and converting the `widget_dispatch.s` run
deleted three fake instructions (`nop`, two `swi 7`, one `aligned_string ""`)
that were framing this data as code.

The 23 records left in assembly are in runs of 1-7 whose last record ends in the
middle of a source line that continues into an unrelated auxiliary table.
`find_range()` refuses that rather than guessing where to cut; the refusal is
the safety property, not a gap to be papered over.

## Assessed and deliberately NOT converted

* **`v10/maincpu/includes/gui_display_struct_data.s`** — already done by an
  earlier lane.  The file emits **zero bytes** (nothing includes it); the live
  source is `gui_display_struct_data.c`, which already carries the 34-byte
  record as a named struct.  Do not spend budget on its 5,161 `.byte` operands.
* **`HDAE5000_RECORD_TABLE`** (0x29C0AA) — already meets the standard in the
  other permitted form: 13 × 24 B emitted field-by-field with a per-field
  comment and an evidence block, and 5,832 of its 6,356 bytes are a verified
  zero gap.  Re-typing it to C would be churn.
* **The SX-WSA1R display-list records** — likewise already field-by-field with
  per-field comments, and `prom_b/wsa1_prom_b.s:60930-60957` names each field
  after the instruction that consumes it.  Nothing to add.
* **`table_data/style_records.s`** (1,000 × 198 B) — the biggest fixed-stride
  grid in the tree, but only **three** of its fields have a reader anywhere in
  v7/v9/v10: `+0x04` (`add xhl,(xwa+4)`), `+0x2a` and `+0x2b` (`ld a,(xbc+42)` /
  `lda xwa,(xbc+43)` → `Strncpy`).  There are only three access sites in all
  three program ROMs.  Converting would replace an already-offset-commented
  generated file with a C struct whose category/style/param-block names would be
  *content*-derived, not reader-derived — a downgrade by this lane's standard.

## Reproducibility

* `scripts/generators/gen_msp_factory_defaults_c.py` — re-derives the MSP `.c`
  from the ROM and asserts every invariant quoted above (`--write` to rewrite).
* `scripts/generators/gen_sndparam_records_c.py` — same for the descriptor runs;
  re-verifies already-converted runs against the ROM on every run.
* `scripts/analysis/uncommented_data_census.py` — the census that picked the
  targets. 1,076,671 B tree-wide before this lane, 1,049,062 B after.
