# Lane brief — full-disassembly push, 2026-09-01

Standing rules for every parallel lane agent working this push. Read this
before touching anything. It exists so the rules are auditable and identical
across lanes rather than paraphrased into each agent's prompt.

## The goal, stated exactly

**Territorial coverage: every byte of every ROM reproduced by real source.**

**Semantic labeling is DEFERRED.** Do not spend budget inventing names. A
region converted to correct, byte-exact, *unnamed* instructions or typed data
is a WIN. A region given beautiful names but still `.incbin` is not.

## What counts as debt — and the trap

Undisassembled means **any byte not reproduced by real source**. That is:

* `.incbin` of a committed blob, **and**
* long `.byte` / `.word` runs that are really un-decoded code or untyped data.

⚠ **`.incbin` count alone is the WRONG instrument.** This project already
shipped a false "territorially complete" claim by counting `.incbin`
directives in a tree whose remaining debt was written as `.byte` — 8,496 bytes
of sound code sat in plain sight passing a test looking for the wrong word.
Measure bytes, not directives.

⚠ C source compiled byte-exact by `clang -target tlcs900` **is real source**,
not debt. Much of the maincpu `.incbin` total is exactly that. Separate the
two before reporting a number.

## The gate is the only certification

`make gate-all` rebuilds every ROM and compares against the dumps: 9 KN5000 +
4 WSA1R = **13 images**. It is green as of `5831d460` and must be green when
you finish.

* Work in **your own worktree** so your build cannot race another lane's.
* Run the gate **in your worktree**, not in the shared tree.
* A conversion that changes one byte is a REGRESSION, not progress. Revert it.
* Before quoting the gate as evidence, be sure it would go red on your change:
  an object built from a stale prerequisite certifies nothing. This tree has
  already been burned by exactly that.

## Repo discipline

* **Never `git add -A`.** Name your paths explicitly. A sweeping add once
  swept 55,000 lines of another lane's work into an unrelated commit.
* **Never `git push`.**
* **Never run `git checkout`, `git stash` or `git reset` in the shared tree** —
  other lanes have uncommitted work and it will be destroyed.
* Commit **frequently and granularly**. Work that is committed survives a
  crash; work in a worktree does not.
* Every commit message needs the toolchain line:

      LLVM: tlcs900_backend@dbb72df07371 (dbb72df073711ef98be1e41f003e04a7022bf120)

  Get it yourself with `cd ~/compartilhado/llvm-project && git log -1
  --format="%D @ %h (%H)"`. **Never pad a short hash into a long one.**

## Preservation — a hard rule from the project owner

**Do not destroy existing comments, documentation headers, or semantic
structures.** Modify them only when you are sure the result is semantically
better. **Never flatten the tree into one file**: per-subject source files are
the required shape, and flattening would be cheating.

## Reproducibility

If a number is worth putting in your report, the thing that produced it is
worth committing, in the same session, next to what it measures — with a
README line saying what question it answers and the exact command. `/tmp` is
volatile and does not count.

## Reporting

Report, for your lane: bytes of debt **before** and **after**, how you
measured (naming the script), the gate result, and anything you could NOT
convert with the reason. An honest "this region resisted, here is why" is
worth more than a number that overstates.
