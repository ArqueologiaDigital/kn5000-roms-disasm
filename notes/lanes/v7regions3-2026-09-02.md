## Two tooling fixes (commit `068ba55a`)

1. **`directive_size()` in `convert_interrupted_region.py` didn't strip
   inline comments.** A `.byte` line's last operand token included the
   trailing `; jrl FileName_UpdateDisplay (v7 displacement)` text an
   earlier hand-annotation pass had attached, which failed
   `LITERAL_OPERAND_RE` and made `find_span()` abort as if the line were a
   real instruction. Fixed by splitting off `; ...` before checking WIDTH
   directive operands (safe -- those directives never take a quoted
   operand). This is the fix that unblocked `FileName_OpSave` above.
2. **`run_v7_worklist_batch.py` overstated converted bytes when
   `convert_interrupted_region_v7.process()` auto-shrank a region.** The
   caller computed `converted = w['size'] - remaining` using the
   worklist's ORIGINAL (pre-shrink) size, not the actual size `process()`
   touched. Concretely: a 139 B region at `audio_control_engine.s:6738`
   auto-shrank to a 2 B untouched-as-`.byte` prefix (0 bytes actually
   converted, confirmed by `git diff` showing **no change at all** to that
   file) but was tallied as "137 B converted". `process()` now returns
   `(actual_size, remaining)` and the caller uses `actual_size`. Reproduce:
   `git log -p 068ba55a -- scripts/converters/`.

⚠ Any of this lane's OWN earlier dry-run printouts that quote "286 B
converted" for a 2-region batch are wrong for exactly this reason -- the
committed, gate-verified truth is 149 B, not 286.

## The interior-label wall (brief's warning), reproduced directly

The lane brief said every remaining well-corroborated v7 region fails an
interior-label check, clustered in `note_voice_mapping.s`,
`dsp_config_sysex.s`, `midi_dispatch_handlers.s`, `midi_serial_routines.s`.
Confirmed empirically, twice (before and after the comment-strip fix):

    python3 scripts/converters/run_v7_worklist_batch.py census-work/v7_region_worklist.json \
        --require-clean --exclude-table-tail --log /tmp/dryrun.json

Of the **15 regions** that are both "clean" (100% of absolute call targets
resolve to pre-existing names) and NOT flagged by the table-tail guard --
the single strictest, safest selection this tree's tooling supports -- all
15 fail with `convert_interrupted_region.py`'s own guard:

    label(s) [...] do not land on any decoded segment boundary --
    aborting rather than guessing where to put them

13 of the 15 are in the four clustered files named above; the other 2
(`sndparam_routines.s`, `audio_control_engine.s`) show the same shape or
net zero real bytes (see the tooling fix above). Per
`convert_interrupted_region.py`'s own comment, this means **the decode
disagrees with the existing framing** for the whole span, not merely that a
label is inconveniently placed -- exactly the brief's reading. This lane
did not attempt to relocate any of these labels or force a partial/shrunk
conversion past the point of disagreement: doing so would repeat the
"wrong start frames fake records indefinitely" hazard the brief documents
elsewhere in `DEBT-INVENTORY-2026-09-02.md`, since a decode that disagrees
with a known-real label past some offset gives no reason to trust the
decode's own reading of anything before that offset either.

Every one of these is far below the brief's ~75% floor and below the

one threshold -- it holds flat from `min_calls>=1` through `>=5`, which
means the pool does not have a "next tier down" the way batches A/C/E/F
did; it drops off a cliff to the same ~30% no matter how the remaining 519
regions are filtered by call count alone.

**This lane stopped here rather than convert at ~30% corroboration.** The
brief is explicit that a batch below ~75% should be flagged and lane work
reconsidered, not pushed through; this is a fresh, direct confirmation of
that threshold being crossed for essentially the whole remaining v7
confirmed-region pool, not just one weak batch within it.

## What the next pass needs

The 15-region interior-label pool is not a queue item for more batch
conversion -- it needs per-region hand reading of WHY the decode disagrees
with the label past a given offset (a genuine head/tail split? a decoder
gap in one of the `SriRR*`/`decodeERPPrefix()` families the debt inventory
already flags as unimplemented? a wrong region boundary from census's
coarse byte-vs-code map?). That is slower, per-region work, not a batch
run. `notes/DEBT-INVENTORY-2026-09-02.md` item 5 (the decode-leg gap) is
the most likely next lead, since `midi_serial_routines.s`,
`midi_dispatch_handlers.s` and `note_voice_mapping.s` are exactly the kind
of MIDI/audio dispatch code most likely to hit an unimplemented addressing
form.
