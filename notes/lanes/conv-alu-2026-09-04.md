# Lane `w26/conv-alu` — the ALU-direct remainder

**Done.** The direct-address shape is now closed except for a backend gap and a
macro-body class. **11,840 of 11,875 sites in 220 files** respelled from a
synthetic mnemonic that carried the address width to the native mnemonic plus a
width-annotated operand, gated one base operation at a time.

This finishes section 8 of `notes/ASSESSMENT-syntax-convergence-2026-09-02.md`
(Option B) — the part that needs no backend change — which
`notes/lanes/conv-width-2026-09-03.md` left as "the next slice and it is
mechanical". It was mechanical. It was also 22% bigger than that note predicted
and it contained one wrong assumption, below.

## ★ The finding: byte-identity is per instruction CLASS

The previous lane measured that a 32-bit register name written against an 8-bit
form means the pair's LOW BYTE — `ldb_da xwa` is `ld a` — and mapped
`xwa->a xbc->c xde->e xhl->l`. Carried into the ALU forms, that map produced
161 `BYTES-DIFFER` refusals. Measured directly, on the same assembler:

    ldb_da xbc, (0x120000)   ->  ...,0x23   LD base 0x20 + 3  =  C   (low byte)
    cpda8  xbc, (0x1000)     ->  ...,0xf1   CP base 0xf0 + 1  =  A   (same index)

**Two conventions live in one backend, split by instruction class.** Applying
the neighbouring family's rule silently would have written a wrong register
name at 2,379 sites — and the byte gate would have caught it, but only because
the sub-opcode moved; a rule that happened to agree on bytes while disagreeing
on meaning would have passed.

So `convert_direct_address_family.py` no longer asserts either rule. It offers
every name of the right class and keeps the one whose encoding equals the line
it replaces. Each name has a distinct sub-opcode, so at most one can match, and
a match is a measurement rather than a guess. Over this lane: 2,379 resolved
index-preserving, 0 low-byte, 0 by exhaustive search, 3,941 already correct,
5,520 with no register operand.

## ⚠ The residue list was read off the NAME, and undercounted by 22%

`conv-width-2026-09-03.md` predicted "9,748 sites over 66 names" by grouping
census names that *look* like direct-address forms. The real set — every
backend mnemonic whose `(ins ...)` contains `directaddr`, intersected with tree
usage — is **95 names, 11,881 sites**. The 29 extra names do not look like the
others: `jp_24`, `call_24`, `lda_24`, `pushdi_24`, `chgda_24` and their `_24`
siblings. Reading the OPERAND LIST instead of the name found them.

★ A census keyed on a naming convention measures the naming convention.

## Refused: 35 sites

* **27 × `lda_24 xwa, (\ParamB|\ParamD)`**, all inside `.macro` bodies in
  v7/v9/v10 `display/scoop_display.s` and `factory_test/test_init.s`. A macro
  parameter cannot be assembled in isolation, so the per-site guard cannot
  certify it — the same class, in the same two files, as the six `ldw_da`
  bodies the previous lane refused.
* **8 × `chgda_24 n, (0x160004)`** in v7/v9/v10 `boot/system_handlers.s` and
  `table_data/kn5000_table_data.s`. `chg` has no memory-operand form in the
  backend: `chg 2, (0x160004)` is *invalid operand* and
  `chg 2, (0x160004:24)` does not parse. Only the synthetic `chgm` takes it,
  and one synthetic name for another is not convergence. **This is a backend
  gap, not a source problem** — a `chg` -> `chgm` alias in
  `TLCS900InstrInfo.td` closes it, and `llvm-project` was out of scope for
  this lane.

Every refusal is listed with its file, line and reason in
`scripts/converters/direct-address-convergence-runs/refused-alu-2026-09-04.csv`.

## What is left of the direct-address shape

Nothing mechanical. 35 sites: 27 macro bodies (out of scope by the lane brief)
and 8 waiting on a one-line backend alias. Everything else that spells a direct
address in the mnemonic is gone from this tree.

The 136,863 synthetic sites that remain are the other two buckets of
`ASSESSMENT-syntax-convergence-2026-09-02.md` §residue — the ~78,364 needing a
backend feature and the ~2,371 refused with evidence — plus the 861 above.
