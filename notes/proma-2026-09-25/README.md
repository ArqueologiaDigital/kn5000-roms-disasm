# Lane `proma`, 2026-09-25 semantic push -- instruments

Lane `proma` owns `wsa1/prom_a/*` (the SX-WSA1R CPU-1 program image, TMP95C061,
base 0xF80000).  Every figure the lane quotes comes from a script in this
directory.

| script | question it answers | run |
|---|---|---|
| `measure_proma.py` | census bytes (CODE / KNOWN-A / KNOWN-B / UNKNOWN / FILLER / research targets) for `wsa1_prom_a.s` alone, data-as-code markers, numeric branches (split by destination image) and numeric ROM-range immediates | `python3 notes/proma-2026-09-25/measure_proma.py [--rev REV]` |
| `srcmap.py` | (library) which label is defined at a prom_a address (from the linked ELF via llvm-nm) and which source line starts there (address comments trusted only where their byte text equals the ROM) | imported by the generators |
| `gen_fcf044_tables.py` | what reads each byte of 0xFCF044-0xFCFDA6 (the old `ModuleTables_FCF044`): lists the 56 reader instructions (45 prom_a, 11 prom_b), checks each reader's instruction shape and that PanelEvent_ToFieldIndex is its index producer, checks the tables tile the span, checks NameChar_AsciiToIndex inverts NameChar_IndexToAscii (96/96); `--apply` writes the typed tables | `python3 notes/proma-2026-09-25/gen_fcf044_tables.py` (dry run is the check) |
| `gen_fc4000_pages.py` | what reads each byte of 0xFC4000-0xFC52F7: the prom_b routines that run its display lists (decimal immediates, hence invisible to a hex search), the arrays they index, and the interpreter-B records whose +7 long points at its name/rectangle tables; asserts every list walks exactly, every array entry lands on a boundary, every op-02 width matches its table, and the objects tile the span; `--apply` writes it | `python3 notes/proma-2026-09-25/gen_fc4000_pages.py` |
| `xref_targets.py` | per census research target, every instruction operand or `.long` in prom_a AND prom_b source (hex or decimal) naming an address inside it -- the form a hex-only grep misses | `python3 notes/proma-2026-09-25/xref_targets.py --census X.json` |
| `gen_ram3800_images.py` | what the RAM-0x3800 module's two initialised-data images hold: derives the layout from the module's literal strides (13, 15, 4) and checks it against the bytes -- self-linked queue/list heads, each node pool one ring, the budget/mask/state constants, exact tiling; `--apply` writes it | `python3 notes/proma-2026-09-25/gen_ram3800_images.py` |
| `retire_zero_runs.py` | are the two big `nop`-run regions (0xFE7A86-0xFE7FB0, 0xFF79EA-0xFF7C64) code? | `gen_panel_test_tables.py` | are 0xF8C8AC-0xF8C8C1 and 0xF94ED8-0xF95117 (framed as code) the panel LED wire maps and the test mode's switch-to-LED tables?  Checks the readers' bytes, the tiling (11 + 9 rows), the map values, and that the only labels inside are three orphans no source line or ROM address names; `--apply` retypes them | `python3 notes/proma-2026-09-25/gen_panel_test_tables.py` |
| `dead_runs.py` | unlabelled instruction runs after an unconditional transfer that contain data-as-code markers and that no branch in the source targets -- the candidate list for data-as-code retirement (each still needs its reader looked for; a `push <ret> / jp (xreg)` continuation shows up here too and is NOT dead) | `python3 notes/proma-2026-09-25/dead_runs.py` |
| `gen_kvlists.py` | what 0xFAF7A6-0xFB178F (the 8 KB under `.LFAF7A5`) is: two identity maps and two tables of 33 key/value record lists, with every reader instruction's bytes asserted at its cited address, list framing (records + 0xFF terminator), contiguity, zero pad; `--apply` writes it | `python3 notes/proma-2026-09-25/gen_kvlists.py` |
| `gen_patchlists.py` | what 0xFB1A3E-0xFB1FFF is: three AND/OR RAM patch lists (11 globals at 0x7F32, and +0x0C / +0x2B of the 32 records at 0x76A2) with their one-entry pointer tables, checked against the three applying routines' operands and loop counts; `--apply` writes it | `python3 notes/proma-2026-09-25/gen_patchlists.py` |
| `certified_forms_prom_a.py` | runs wsa1/scripts/converters/convert_certified_forms.py restricted to prom_a: the `.byte` lines the WSA1 census certifies as single instructions the assembler now spells byte-identically; `--apply` rewrites them | `python3 notes/proma-2026-09-25/certified_forms_prom_a.py` |
| `spell_byte_branches.py` | which `.byte` lines hold a single branch (`jr`/`djnz`/`calr`/`call (xreg)`, per their byte+rendering comment), and rewrites each as the instruction with a label target (reused or inserted) so the gate checks the displacement | `python3 notes/proma-2026-09-25/spell_byte_branches.py [--apply]` |
| `symbolize_prom_a_r1.py` | the shared branch symboliser with ONE rule relaxed for prom_a: a call into prom_b (0xF00000-0xF7FFFF, the other half of CPU 1's address space) no longer marks a block "incoherent" (R1); every other guard and `--verify` unchanged.  It execs the shared script's source with that one asserted replacement | `python3 notes/proma-2026-09-25/symbolize_prom_a_r1.py --image prom_a --only prom_a/wsa1_prom_a.s [--apply --verify]` |
| `symbolize_prom_a_addresses.py` | replaces numeric CPU-1 ROM-address operands (`.long`, `call`/`jp` into prom_b, `ld`/`add`/`lda xRR`) with the label already at that address -- prom_a's own labels directly, prom_b's through one generated `.set` equate block; code forms only where unidasm sees the same instruction and operand (R5); `--check-equates` flags prom_b renames | `python3 notes/proma-2026-09-25/symbolize_prom_a_addresses.py [--apply \| --check-equates]` |
| `reframe_panel_tables.py` | are the eleven small tables after the panel-event routines (0xF8A530-0xF8B08A, 0xF8BE4D) data framed as code?  Asserts each reader's bytes at its address, derives the count from the reader's bound, checks each table ends where real code resumes; `--apply` typed them (names/headers since corrected by the next script) | `python3 notes/proma-2026-09-25/reframe_panel_tables.py` |
| `retitle_panel_tables.py` | what those tables are, from the ACTION-LIST POOL that dispatches their readers: which handlers are live (pool records per handler, C1), the event classes of their groups (C2), that 0xF8A500-0xF8A60C and 0xF8BE36-0xF8BED0 are twins of IndexToBitMask8/16/32 (C3), that 0xF8A44B-0xF8A7FF is named by nothing outside it (C4/C4b), twin tables (C5), the V2 keypad handler = the V1 keypad path (C6) | `python3 notes/proma-2026-09-25/retitle_panel_tables.py` |
| `gen_midiin_param_headers.py` | what each of the nineteen MIDI-in 32-record tables (0xFA84C8-0xFA8BA7) holds: asserts each table's one reader (`ld XIX,<table>`), the part bound `cp A,0x1F`, the record walk into the 0x1950 parameter record, the abutment, and ties every number back to MidiOut_ParamNumberTable / MidiOut_ParamClassTable; `--apply` writes the headers | `python3 notes/proma-2026-09-25/gen_midiin_param_headers.py` |
| `gen_param_list_headers.py` | what indexes Dispatch_By_60F080: asserts that List2030_TranslateToQueue2C00 loads each RAM 0x2030 record (List2030_LoadRecord) before the dispatch, that the eleven controller entries 0xB1-0xB5/0xB8-0xBD and MidiIn_ControlRecordHandlers load the same part-mask cell per number, that the MIDI-in tables pin each number to its controller, the fan-out loops, the byte-wise queue append, and the `call` that disproves Queue2C00_PublishStaged's "no caller" (M1-M8); `--apply` (ran once) renames and writes the headers | `python3 notes/proma-2026-09-25/gen_param_list_headers.py` |
| `gen_panel_actions.py` | which routines PanelGroupActionListPool dispatches (labels them, retypes the handler field as `.long <label>`), and what the RAM 0x7F12 assignment bytes are: the firmware's two assignment -> parameter-number chains equal the MIDI-in controller -> number map, so the bytes are MIDI controller numbers (0x81 = channel pressure) (A1-A4); `--apply` / `--headers` ran once | `python3 notes/proma-2026-09-25/gen_panel_actions.py` |
| `gen_message_pairs.py` | what PtrTable_F99121 (0xF99121-0xF993C4) is: its three readers (sub_F99098 via +0x298 and at +0x200, sub_F9904D at +0x218) split it into the 64 message-id (start,end) display-list pairs, 3 interpreter-B pairs, 32 argument handlers and 3 language pointers (Q1-Q4); `--apply` ran once, then `symbolize_prom_a_addresses.py --apply` named the prom_b lists | `python3 notes/proma-2026-09-25/gen_message_pairs.py` |

| `gen_button_tables.py` | what PtrTables_F95C95 (0xF95C95-0xF95E81) is: two screens' 32-entry BUTTON handler tables (read by their objects' +8 BUTTON methods, bound 0x1F) and a stale copy of both (its second half = table 2 + 0xED, its first half follows table 1 code for code, its default lies inside table 2), and the stray byte is the copy's word-4 top byte (K1-K5); `--apply` ran once | `python3 notes/proma-2026-09-25/gen_button_tables.py` |
| `comment_loss.py` | which comments an edit dropped, split into regenerated address-only comments and OTHER lines that need a justification | `python3 notes/proma-2026-09-25/comment_loss.py [--base REV] [--rename-map F]` |

Definitions are the lane worklist generator's (`scripts/analysis/lane_worklists.py`)
and the branch symboliser's (`scripts/converters/symbolize_numeric_branches.py`);
`measure_proma.py`'s docstring states them.  The certification is never these
numbers: it is `make gate-wsa1` (byte identity of all four WSA1R images) plus
`make -C wsa1 images-check` for the PNG-backed bitmap rows.
