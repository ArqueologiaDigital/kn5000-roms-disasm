# region 4: 0x024069..0x025CCA
# Per-voice tone-generator parameter marshalling: the code that packs pitch/level/pan
# words into the IC303 staging block at 0x0451CC and resolves the physical TG slot.
#
# NOTE ON METHOD (read before integrating): every address in this region ALREADY carries a
# real, hand-maintained symbol in the authoritative LLVM build
# (rebuilt_ROMs/kn5000_subprogram_v142.llvm.elf, 176 symbols in range). The proposals
# below therefore adopt the authoritative build's names VERBATIM so that
# symbols/subcpu_symbols_reference.txt (which still shows LABEL_xxxxxx at those addresses)
# stops disagreeing with the ROM that is actually built. Integration is a pure text
# substitution, zero semantic risk. The remaining 14 addresses already have non-LABEL_
# names in the reference file that CONFLICT with the build's names; per the rules those are
# left alone and argued in [UNCERTAIN] at the bottom.
#
# THE ONE STRUCTURAL FACT THAT EXPLAINS THE WHOLE REGION (verified, not inferred):
# 0x0451CC is a 68-byte tone-generator parameter staging block in DRAM. Nothing in this
# region touches 0x100000/0x100002 directly. The block is handed to
# ToneGen_WriteVoiceParams (0x02D0F2 region, `lda_24 xbc, 0x0451cc` appears 47x in the
# firmware) together with WA = physical TG slot number, and that routine walks the block
# emitting one address-latch + data pair per word. Word offset -> TG register (all + slot):
#   +2  0x0451CE -> reg 0x040   waveform / multisample select
#   +4  0x0451D0 -> reg 0x080   voice mode; written first with bit15 SET and again at the
#                               end with bit15 CLEAR -- the key-on latch strobe pair
#   +6  0x0451D2 -> reg 0x0C0
#   +8  0x0451D4 -> reg 0x100
#   +10 0x0451D6 -> reg 0x140
#   +12 0x0451D8 -> reg 0x180
#   +14 0x0451DA -> reg 0x400   (also written alone by ToneGen_WritePanReg)
#   +16 0x0451DC -> reg 0x440   +18 0x0451DE -> 0x480   +20 0x0451E0 -> 0x4C0
#   +22 0x0451E2 -> reg 0x500
#   +24 0x0451E4 -> reg 0x800   main volume/level (0xFF80 = mute)
#   +26 0x0451E6 -> reg 0x840   +28 0x0451E8 -> 0x880   +30 0x0451EA -> 0x8C0
#   +32 0x0451EC -> reg 0x900   +34 0x0451EE -> 0x940   +36 0x0451F0 -> 0x980
#   +38 0x0451F2 -> reg 0x9C0   +40 0x0451F4 -> 0xA00   +42 0x0451F6 -> 0xA40
#   +56 0x045204 -> reg 0x1C0   +58 0x045206 -> (ExtParams_15 path)
#   +60 0x045208 -> reg 0x580   +62 0x04520A -> reg 0x5C0   +64 0x04520C -> reg 0x600
#   +66 0x04520E -> reg 0x600 (alternate/high path)
# Per-voice software record: 0x041300 + channel*0x11F. Fields used here: +19/+23/+35/+39
# are 32-bit pointers (part record, tone record, patch record, performance record);
# +42/+44 hold the packed reg-0x100 / reg-0x140 pair; +45 the packed reg-0x800 level word;
# +60/+62/+64 cached level/pan words; +0x4C (0x04134C) is a GLOBAL mode byte (values 5 and
# 6 select alternate expression handling); +0x8D/+0x8E (0x04138D/0x04138E) are per-voice
# routing nibbles.
# Physical TG slot state array: 0x04424E, stride 0x1B (27) bytes, 0x80 entries, ending
# exactly at 0x044FCE (which the firmware references as a separate variable -- that is the
# proof of the 0x80 bound). Sub-voice view of the same array is 0x044257 = 0x04424E + 9.
