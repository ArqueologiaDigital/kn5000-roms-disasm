# region 15: 0x03A933..0x03D403
# The DSP filter-coefficient math (biquad + second-order-section), the DSP bytecode /
# parameter-write engine that feeds it, and -- despite their names -- the KEYBED scanner and
# two float helpers.
#
# INTEGRATION NOTE (read first):
#   The AUTHORITATIVE LLVM build already carries a real name for almost every address in this
#   range (verified with `llvm-nm -n rebuilt_ROMs/kn5000_subprogram_v142.llvm.elf`).
#   symbols/subcpu_symbols_reference.txt is what lags: ~70 of its entries here are still
#   LABEL_xxxxxx.  For those this file gives the ELF name verbatim plus the `replaces=` field,
#   so integration is mechanical, AND the doc header the project actually wants.
#   What is genuinely NEW here is 29 names for code the converter emitted inside `.byte`
#   runs and that therefore has NO symbol at all:
#     * 24 opcode-dispatch arms at 0x03CBDE..0x03CE9E (reached by a computed jump), and
#     * 5 bytecode-handler entries at 0x03C568..0x03C7BB inside DSP_Bytecode_Programs.
#   NOTHING in this file renames an existing non-LABEL_ symbol; disagreements are in
#   [UNCERTAIN] only.
#
# ★ WHAT THIS REGION ACTUALLY DOES
#
#   1. 0x03A933..0x03C160  Floating-point DSP filter design.  Two families:
#        DSP_BiquadCoeff_Compute (0x03A933) -- bilinear-transform biquad.  Prewarps with
#          K = tan(pi*f/Fs) using the double constant pi/44100 = 7.123792865e-05.
#        DSP_SOS_Coeff_Compute (0x03B646) -- RBJ-cookbook second-order section.  Uses the
#          full angle w0 = 2*pi*f/Fs = 1.424758573e-04.
#      Both take the band's centre frequency from the ISO 1/3-octave table at 0x012397
#      (40, 50, 63, 80 ... 16000 Hz, 27 floats) and a gain in dB formed as
#      raw*0.5 - 12.0  (so 0.5 dB steps over +/-12 dB), convert it to a linear factor with
#      A = 10^(dB/20), assemble the five biquad taps, divide them all by a0, scale by
#      2^22 (=4194304.0) -- the last tap by 2^23 (=8388608.0) -- convert to integer and push
#      them to the DSP.  ★ SAMPLE RATE IS 44100 Hz, proven by the constants.
#
#   2. 0x03C067..0x03C160  DSP_MixerCoeff_Compute -- integer (Q15/Q16) mixer gain, writes DSP
#      registers 0xD0 and 0xD3.
#
#   3. 0x03C161..0x03CFED  The DSP write plumbing: a small BYTECODE INTERPRETER (six opcodes)
#      that replays canned register-write programs, a PARAMETER-WRITE ENGINE that walks a
#      tagged variable-length table, and a PER-PARAMETER TRANSLATOR whose 28-way opcode
#      dispatch calls the curve/interpolation functions of regions 13-14 and then one of
#      DSP_WriteOscParam / DSP_WriteFreqParam / DSP_WriteCoeffData_5B_Direct.
#      Every hardware write funnels through DSP_DispatchCommand/DSP_DispatchData (0x036A2E /
#      0x036A4F) with a chip selector: 0 = DSP1 (uPD6383, IC311, port 0x130000),
#      1 = DSP2 (MN19413, IC310, bit-banged SPI).  The chip id for an effect slot comes from
#      the byte table at 0x01ED6D.
#
#   4. 0x03CFEE..0x03D342  ★ MISNAMED: this is the KEYBED, not the tone generator.  It reads
#      0x110002 (status) / 0x110000 (data) -- the KEYBED port per kn5000.cpp -- turns key
#      events into 3-byte MIDI note-on messages in the buffer at 0x004A42 and DMAs them to the
#      MAIN CPU.  This is the "keybed service" the brief locates at 0x03D01E.
#
#   5. 0x03D34D..0x03D403  Three float helpers used by the filter math.
#
# ★★ THE FP LIBRARY'S OPERATION NAMES ARE SYSTEMATICALLY WRONG (measured, see [UNCERTAIN]).
#   The format is plain little-endian IEEE-754 (double: bias 0x3FF; single: 4 bytes).  What the
#   routines really do, proven from FP_DP_AlignMantissa / FP_DP_MulAdd / FP_DP_Mul_Outer:
#       FP_xx_Mul        (0x03E10E/0x03E15A)  = ADD/SUB   (aligns exponents, adds mantissas)
#       FP_xx_Add_Outer  (0x03E290/0x03E2C0)  = MULTIPLY  (adds exponents, 64x64 mantissa mul)
#       FP_xx_Mul_Outer  (0x03E3F6/0x03E4B4)  = DIVIDE    (subtracts exponents)
#       VoiceFloat_SubDP/SubSP (in this region) = DIVIDE   (they wrap *_Mul_Outer)
#       FP_DP_NegMantissaLS  (0x03DCF2) = float -> double widening
#       FP_DP_NormalizeMantissa (0x03DD6C) = double -> float narrowing
#       FP_SP_Decode_ReadSign (0x03D44C) = float -> integer
#       VoiceFloat_CompareAndConvert (0x03D533) = pow(base, exponent)   [called with 10.0]
#       VoiceFloat_MulAddDispatch (0x03D4C9) = tan(x)                   [biquad prewarp]
#   Every doc line below states the REAL operation, not the label.

[ROUTINE] 0x03A933 DSP_BiquadCoeff_Compute  replaces=LABEL_03A933  confidence=high
; Designs one bilinear-transform biquad from the DSP parameter stream and writes its five
; coefficients to the DSP.  Reached only from the opcode-0x70 dispatch arm (0x03CD96).
; Frame: 236 bytes of locals + `push IZ`.  Register args WA / BC / DE are forwarded to
; DSP_FilterLUT_Fetch.  Five stack args, popped with `retd 0x10` (16 bytes), pushed by the arm
; in this order: (1) long = the parameter-stream pointer, (2) word = the caller's running
; status accumulator (IZ), (3) long, (4) word, (5) long = pointer to the caller's status word.
; Returns XHL = the ADVANCED stream pointer; also stores the accumulated write status (IZ)
; through arg 5.
; Flow:
;   1. calls DSP_FilterLUT_Fetch (0x03A620) which consumes the stream header, writes the
;      ALGORITHM SELECTOR (the low nibble of the header byte) into a local, hands back the band
;      frequency and gain as floats, and returns the advanced stream pointer (kept at frame
;      +0x00FE and returned verbatim by the epilogue).
;   2. three-way switch on that selector: 2 -> DSP_BiquadCoeff_Algo2, 1 -> ..._Algo1,
;      0 -> falls through to the Algo0 body.  ★ ANY OTHER VALUE JUMPS STRAIGHT TO
;      DSP_BiquadCoeff_Epilogue AND WRITES NOTHING TO THE DSP -- silently.
;   3. Algo0 body: widen the cutoff to double; w = f * (pi/44100) [FP_DP_Add_Outer = multiply];
;      K = tan(w) [VoiceFloat_MulAddDispatch]; narrow to float; build the {1,-2,1}-shaped
;      numerator from the float literals at 0x012F5F..0x012F6B; A = 10^(gain_dB/20) via
;      VoiceFloat_SubSP (divide by 20.0) then VoiceFloat_CompareAndConvert (pow, base 10.0 at
;      0x012F73); combine into b0,b1,b2,a1,a2.
; Hardware: no direct MMIO -- everything goes through DSP_WriteOscParam (0x0387E6) and
; DSP_WriteCoeffData_5B_Direct (0x0388B3) in the Fixup block.

[ROUTINE] 0x03C067 DSP_MixerCoeff_Compute  replaces=LABEL_03C067  confidence=high
; Computes a two-stage integer mixer gain and writes it to DSP registers 0xD0 and 0xD3.
; Called twice from region 11 (0x034360-area, the output-routing layer).
; In:  WA = index A, BC = curve index, DE = index B.  32 bytes of locals + `push XIZ`, `ret`
;      (no stack args).
; Body: g = long[0x000131CF + 4*BC] >> 15;  g = MulAccum64(g, long[0x00F140 + 4*WA] >> 16);
;       g = MulAccum64(g, long[0x00F140 + 4*DE] >> 15)  -- FP_MulAccum64 at 0x03D8CA is a
;       32x32 -> 64 fixed-point multiply-accumulate, so this is Q15/Q16 arithmetic on the
;       live per-slot volume array in DRAM at 0x00F140.
;       The same slot is then run through FP_SP_CallWithBuf8 / FP_SP_Decode_ReadSign to get a
;       second, float-derived integer.

[UNCERTAIN] ★★ The FP library's arithmetic names are swapped, and it matters for this region.
; Measured from the bodies (addresses are outside region 15, so nothing is proposed):
;   FP_DP_Mul (0x03E10E) / FP_SP_Mul (0x03E15A) call FP_xx_AlignMantissa then

;     Aligning exponents and adding mantissas is ADDITION, not multiplication.
;   FP_DP_Add_Outer (0x03E290) / FP_SP_Add_Outer (0x03E2C0) call FP_xx_MulAdd, whose body at
;     0x03EBCE ADDS the exponents (`add (XWA+0x00),HL`), XORs the signs and calls
;     FP_MulMantissa64x64 (0x03ED0E).  That is MULTIPLICATION.
