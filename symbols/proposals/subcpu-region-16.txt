# region 16: 0x03D404..0x03EEFF
# The complete C-runtime soft-float / libm library (IEEE-754 single + double), plus the
# libm entry points pow/sin/cos/tan/exp/log/modf/frexp/ldexp and the integer 64-bit
# divide helpers. It contains NO audio, voice or tone-generator code: its only clients
# are the DSP effect-parameter curve routines at 0x038F00..0x03BFFF (DSP_VolumeCurve_FP,
# DSP_ReverbCurve_FP, DSP_ParamEQ_Curve_FP, DSP_BiquadWarp_FP, ...) which are entered
# from the dispatch block at 0x03CC38..0x03CECA. Region ends at FP_Library_End_Pad
# 0x03EE75; 0x03EE76..0x03EEFF is 0xFF fill.
#
# IMPORTANT, READ FIRST: every address in this region is still LABEL_xxxxxx in
# symbols/subcpu_symbols_reference.txt, but the authoritative LLVM source
# (v142/subcpu/subcpu_fp_math.s) already carries names for all 308 of them. Per the
# "never rename a real name" rule this file proposes the EXISTING LLVM names verbatim so
# the two sources converge mechanically. Several of those names are provably WRONG
# (multiply/add/divide are mutually swapped, single/double are swapped in the
# conversion helpers, and eight libm functions carry audio-sounding Voice*/DSP_*
# prefixes). Each such case is documented in its header and collected in the
# [UNCERTAIN] block at the end for a human to decide.
#
# THE UNPACKED WORKING RECORD used throughout (built by FP_DP_Decode / FP_SP_Decode,
# consumed by FP_DP_Encode / FP_SP_Encode), verified against every producer/consumer:
#   +0 int16   unbiased exponent
#   +2 uint8   "special" flag: 1 = zero/underflow, 8 = NaN/overflow marker
#   +3 uint8   sign (bit 7)
#   +4 uint32  mantissa low
#   +8 uint32  mantissa high   (double only; the single-precision record is 8 bytes)
#
# CALLING CONVENTION, verified across ~30 call sites: leaf helpers take XWA = destination
# pointer, XBC = source A pointer, XDE = source B pointer, and return nothing (result via
# *XWA). The libm entry points are ordinary C functions returning a double, i.e. the
# caller pushes, right to left, the arguments and then a pointer to an 8-byte result
# buffer, and cleans up.
#
# ERRNO: all range/domain errors write the word at 0x040C22 with 0x21 (EDOM=33) or
# 0x22 (ERANGE=34). Measured: the ONLY code that ever READS 0x040C22 is pow() itself
# (0x03D72F and 0x03D751). No DSP/audio caller checks it, so every domain and range
# error in this library is silently converted into 0.0, 1.0 or DBL_MAX.

[DATA] 0x03D978-0x03D989  ToneGen_Compare_Tables - relational-operator result rows
; Three 6-byte rows of C booleans, indexed by the relation selector passed in BC (to
; FP_DP_CmpZero64 / FP_SP_CmpZero32) or DE (to the two-operand comparators at 0x03D2AC
; and 0x03D306). Row base addresses: 0x03D978 = "operands equal", 0x03D97E = "a < b",

; symbols/subcpu_symbols_reference.txt is misleading: the table has nothing to do with
; the tone generator. 0x03D977 is a 0xFF pad byte.

[ROUTINE] 0x03D98A VoiceFloat_BlendAndMerge  replaces=LABEL_03D98A  confidence=high
; The shared sin/cos kernel. C signature f(double *result, double x, double a, int neg),
; where a = |x| for sin() and |x| + pi/2 for cos() - which is exactly why one kernel
; serves both (sin(|x| + pi/2) = cos(x), cos being even). Body:
;   (1) if |x| >= 2^31 (exponent word test against 0x41E0) -> errno = ERANGE,
;       result = 0.0 (0x01F68E). Argument reduction is impossible past that point.
;   (2) n = round(a * (1/pi)): multiplies by the constant 0.3183098861837907 at
;       0x00F396 (= 1/pi), splits with DSP_VoiceBlend (= modf), and rounds up when the
;       fraction is >= 0.5 (constants 0.5 at 0x01F696 and 1.0 at 0x01F69E).

;       (-1)^n sin(x).

;       pi_hi = 3.1416015625 at 0x00F39E and pi_lo = pi_hi - pi = 8.908910e-06 at
;       0x00F38E (negated through FP_DP_CopyOrNegate8).
;   (5) if |z| <= 2.3283e-10 (0x00F3A6) the polynomial is skipped and z is returned.
;   (6) otherwise Horner on z^2 with the eight coefficients 1/3! .. 1/17! at
;       0x00F34E, F356, F35E, F366, F36E, F376, F37E, F386, then result = z + z*poly.
;   (7) finally, if the sign flag is set, negate.
; The coefficient values read out of the ROM (0.16666666666666666, 0.008333333333333165,
; 1.984126984120184e-04, 2.7557319210152756e-06, 2.5052106798274583e-08,
; 1.605893649037159e-10, 7.642917806891047e-13, 2.7204790957888847e-15) are the odd
; reciprocal factorials to double precision and are what identifies this as sin.

[UNCERTAIN] Whether the log() series at 0x03E7E6 can actually fail to terminate on real
inputs. The terms are z^(2k+1)/(2k+1) with |z| < 1 after the sqrt(2)/frexp reduction, so
it should converge in a few dozen passes, and a diverging case would saturate to DBL_MAX
and compare equal. But the loop has no pass counter while its sibling exp() has one
(300), and the exit condition is an exact bit-equality of two doubles, so a
round-to-nearest limit cycle cannot be ruled out from static reading alone. This needs a
run-time check, not more disassembly.
