# region 9: 0x02EC38..0x031119
# The TONE/EFFECT PARAMETER-EDIT command layer: four separate opcode dispatchers that decode
# 6-byte command records arriving from the main CPU, write the decoded value into the part
# record / patch record / DSP parameter shadow RAM, re-apply the affected algorithm to every
# voice the part owns, and (for three opcode families) DMA the resulting edit buffer BACK to
# the main CPU.  It also contains the DSP coefficient-window readers that AUDIO_PROCESS_DSP
# (0x035AC8) uses to answer main-CPU queries.
#
# INTEGRATION NOTE (read first):
#   The AUTHORITATIVE LLVM build already carries a real name for 42 addresses in this range;
#   symbols/subcpu_symbols_reference.txt carries LABEL_xxxxxx for 36 of them.  Every entry
#   below that has `replaces=LABEL_xxxxxx` proposes THE EXISTING LLVM NAME UNCHANGED -- it is
#   a reference-file sync plus a doc header, never a rename.  Entries without `replaces` are
#   genuinely new: those addresses have no symbol in either file.  6624 bytes of this region
#   sit inside three converter-produced "_ExtData" blobs that are CODE, not data (see the
#   [UNCERTAIN] on naming at the end).
#
# ★ THE FOUR COMMAND DISPATCHERS (all take XWA = pointer to a 6-byte command record)
#   record layout, identical in all four:  +0 (unused here)  +1 part index 0..0x19
#                                          +2 opcode         +3/+4 value (lo/hi or a pair)
#                                          +5 a "kind" tag checked for 0x07 / 0x0F
#   0x02ED80  20-way, opcodes 0x00..0x0D and 0x13..0x18   (called from 0x031AA3)
#   0x02F830  19-way, opcodes 0x15..0x27 step 3, then a 31-way second stage on 0x11..0x65
#             (called from 0x031AB3)
#   0x02FF3A  per-DSP-unit, C = unit 0..3, opcodes 0x00..0x06 / 0x17 / 0x26..0x38 / 0x4D..0x50
#             (called four times from 0x031AD5, 0x031ADF, 0x031B01, 0x031B0B)
#   0x030428  writes one patch byte then ALWAYS replies to the main CPU (0x031B2B)
#   All four are ultimately reached from DSP_SetCoeff_MasterConfig (0x031795), the top-level
#   handler for this command class.
#
# ★ DATA STRUCTURES USED THROUGHOUT (all read off the code in this region)
#   PART table    0x041368, 26 x 0x11F bytes, index = part 0..0x19.
#                 +0x00 flags word: bit 0 = "part is allocated"; (word & 3) == 3 required for
#                       parts > 2 before an allocation is honoured
#                 +0x06 long pointer to the PATCH record (symbol Part_PatchRecord_Ptr)
#                 +0x0A flags word 2, bit 14 tested by the output-config dispatchers
#                 +0x19 Part_UserToneIndex   +0x1A tone/bank byte
#                 +0x66 one byte written with L at the end of two command paths
#                 +0x6E + slot*0x25, slot 0..3: four operator-slot records whose FIRST 4 bytes
#                       are a long pointer to a SLOT DESCRIPTOR
#   PATCH record  (part+0x06)  +0x10 gate byte, (b7:b6)==01 selects an alternate handler
#                 +0x14/+0x17/+0x1A/+0x1D/+0x20/+0x23/+0x26  seven 3-byte parameter groups
#                 +0x5D  low nibble = ALGORITHM TYPE 0..0x0B, the key the whole region
#                        dispatches on
#                 +0x5E..+0x65  eight effect-parameter bytes filled from the descriptor table
#   SLOT desc.    +0x27, +0x2B, +0x2C, +0x2D, +0x2E(low 6 bits), +0x3B, +0x3C, +0x3E(low 6)
#                 +0x36 & 7 = slot "shape" 1..5, selects which of the cached bytes apply
#                 +0x4D..+0x50  the four bytes the parameter cache reads and writes
#   PARAM SHADOW  0x044FCE (existing symbol UserTone_VelSplit_Base -- see [UNCERTAIN]).
#                 One byte array with six disjoint sub-ranges, all indexed differently:
#                 +0x000 + opcode                     opcodes 0x11..0x65 (0x02F830 family)
#                 +0x066 + unit*0x51 + (opcode&0x7F)  DSP unit 0..3   (0x02FF3A family)
#                 +0x1AA + (opcode>>6)*0x0B + (opcode&0x3F)           (0x0301E3)
#                 +0x1D8 + index                      read back by DSP_VoiceParamReadWrite
#                 +0x1E0 + slot*5    5-byte per-slot cache (0x02FD85 / 0x02FED1)
#                 +0x1F4 + index*5   5-byte per-slot cache, bank flavour (0x03025F/0x0303B4)
#                 Each 5-byte cache entry is [shape, b0, b1, b2, b3].
#   GLOBALS       0x0451A4 = part currently selected for editing (0xFF = none, set at
#                 0x034C3B); 0x0451A5 = saved previous value, WRITE-ONLY (see findings);
#                 0x0451A6..0x0451AC = global transpose/vibrato/filter/pan offsets applied by
#                 DSP_AdjustVoiceParams; 0x045204..0x04520C = EG scratch;
#                 0x045210 = 13-byte DSP coefficient staging buffer, +6 is where every reader
#                 in this region starts writing; 0x045310 / 0x045314 = long pointers to the
#                 DSP coefficient window base and to its descriptor block;
#                 0x04531C = ToneDB_RamBankA, and (ToneDB_RamBankA + 0x72A7) is the CURRENT
#                 EDIT-BUFFER INDEX byte that every reply address in this region is built
#                 from.  Edit buffers live at ToneDB_RamBankA + 0x4AA7 + index*0x50.
#
# ★ SUB->MAIN REPLIES.  Exactly four call sites of InterCPU_E1_DMA_Transfer (0x020DB3) exist
#   in this region: 0x02ED7C, 0x03025B, 0x03052D, 0x03060E.  All four target the main CPU
#   window at 0x001E0000.  Nothing else in the region talks to the main CPU.
#
# The [DATA] entries whose addresses are below 0x02EC38 are THIS region's dispatch tables;
# they physically live inside the large unnamed constant pool that runs from
# PitchDetune_OffsetTable (0x00F787) to CALL_TABLE_12159 (0x012159) and have no symbol today.

; from the caller.  Either way 0x0D bytes are copied to the caller's buffer and HL = 0x0D is
; returned.  Caller: 0x03198B.
