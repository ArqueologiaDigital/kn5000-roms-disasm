\chapter{Scope of this edition}\label{ch:limits}

This reference covers message framing, the bulk-dump transfer protocol, the parameter
address space, the sound and drum areas, the effects, the universal messages, error
reporting, the differences between the two models, and the layout of the \textsc{sound}
and \textsc{combination} blocks a dump carries.

\section{Deliberately outside it}
\begin{description}
\item[What a parameter does to the sound.] Chapter~\ref{ch:params} enumerates all 108
  addresses of the \bytes{00} area with their name, length, bit mask, accepted values and
  position in a dump, and chapter~\ref{ch:sound} does the same for the sound areas. What a
  setting \emph{does} is the user manuals' subject, not a protocol reference's.
\item[The effect block diagrams.] The guide draws the signal path of each of the 56
  effects. Chapter~\ref{ch:effects} gives their parameters instead.
\end{description}

\section{What the guide names but does not pin down}
An implementation of this reference --- a librarian that reads and writes every address in
it --- was built alongside this edition, and the count of what it could \emph{not} turn into
a control is the most honest measure of where the published tables stop. Three gaps, all of
them the guide's rather than this document's, and each one a place where a reader must
either measure the instrument or leave the parameter alone.

\begin{description}
\item[Bytes the guide addresses but does not break down.] In \textsc{normal sound}, 36 of
  137 fields carry no bit layout and 20 carry no range; in \textsc{drum sound}, 29 of 99 and
  8 respectively. The guide names each one and gives its address, and stops there. Several
  could be split by reading the prose beside them --- \textsc{tone on/off} notes ``two bits
  per tone, 4th 3rd 2nd 1st'' --- but a layout inferred from a sentence is a guess wearing a
  table's clothes, and chapter~\ref{ch:sound} prints the note instead.

\item[Ranges given only as prose.] A handful of parameters have a range the guide states
  in words rather than endpoints --- ``0.2 per cent per step'' and the like. Those are
  printed as the note, not converted into a span, because the conversion would be a reading
  of the sentence rather than a transcription of a number.
\end{description}

\begin{note}{Two gaps this edition closed by reading a column}
Earlier drafts listed two more, and both turned out to be the guide stating something
nobody had transcribed rather than the guide failing to state it.

The first was which conversion table each effect parameter uses. It is the \textsc{data}
column of every \textsc{dsp effect} page, and it is now given for all 435 parameters.

The second was the \textsc{value} numbering where several fields share a byte. That is the
\textsc{value} column of the same pages, printed outright on every row, and it is now given
for all 56 effects.

Both had been described as unstated on the strength of not having looked at the right part
of the page. That is the same error this project has made repeatedly with these image-only
manuals, and the remedy is the same: render the page before concluding it is silent.
\end{note}

\section{Open, and what would close it}
\begin{description}
\item[Why a parameter reply arrives twice.] Against the emulated instrument every answer
  to a \bytes{2B} arrived \emph{two} times, about 20\,ms apart, in three runs out of four
  and once in the fourth. A receiver that stops at the first is fine; one that pairs
  requests with replies by counting them is not, which is why it is written down here
  rather than dismissed as noise. The likely place is that both outer dispatch tables send
  commands \bytes{1A}--\bytes{1F} to the same handler, where \bytes{21} and \bytes{22}
  reach the session entry on the interrupt side only --- but nothing measured so far
  isolates it, and only one \textsc{midi in} is wired in the emulation, so it is not a
  doubled input. Whether a real instrument does it too is unknown.

\item[What refuses a category dump request.] Its own panel gate admits the
  \textsc{sysex bulk dump} screen, and a request sent there was still refused. The refusal
  is downstream of that test and has not been traced.

\item[Other firmware.] This reference describes one ROM set, and it can now name which.
  The instrument does not report an ``operating system version'' at all: it has a
  \textsc{rom version} screen that reports \emph{three} ROMs separately, as
  \textsc{wsa-a}, \textsc{wsa-c} and \textsc{wsa-d}. Each program image ends with the
  linker's own build stamp in its last sixteen bytes, and the screen's code reads them ---
  one routine twenty bytes from the caption checks the stamp's tail, another loads from
  the same place. The set read here is

  \begin{center}
  \textsc{wsa-a}~822 \qquad \textsc{wsa-c}~230 \qquad \textsc{wsa-d}~54
  \end{center}

  and a reader can compare all three against their own instrument in one screen. Three
  stamps for four images is not an omission: \textsc{wsa-a} spans two of them, which is why
  the screen lists three.

  So ``version 2'' is a label the community archive puts on a file set, not a number the
  machine reports, and there is no single version for a reader to match. Describing a
  different ROM set is a different document and would need those ROMs; the three numbers
  above are what makes it possible to tell that you are holding one.
\end{description}
