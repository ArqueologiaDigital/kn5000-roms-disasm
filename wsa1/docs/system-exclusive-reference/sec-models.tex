\chapter{SX-WSA1 and SX-WSA1R}\label{ch:models}

The SX-WSA1 keyboard and the SX-WSA1R rack module ship \textbf{the same ROMs} --- not
merely the same program built twice, but the same images --- and speak the same System
Exclusive protocol. Two features are nonetheless available on the keyboard and not
on the rack, in both directions, and the two models put different bytes in the model
triple. Nothing else in the System Exclusive implementation depends on which model it is:
the framing, the checksum, the handshake, the error reporting, the parameter address space
and every other bulk-dump category are identical.

\begin{caution}{On the rack, a SEQUENCER dump sends nothing and says nothing}
The rack's \textsc{sysex bulk dump} menu has no \textsc{sequencer} row: it is not drawn,
and the soft key that would select it does nothing. The category can still be reached over
MIDI, by a dump request addressed to \bytes{60 00 00}, and as part of \textsc{total
keyboard}. In both cases nothing is transmitted --- not even the end-of-category message
that closes every other transfer. A librarian waiting for data will simply time out.

On the rack the transfer-progress screen likewise lists only \textsc{sys,part\&midi},
\textsc{sound} and \textsc{combination}.

Technics' own guide points the same way: the photograph it prints of the \textsc{sysex
bulk dump} menu, the one showing all five rows, is captioned \textsc{(wsa1)} --- the
marker the guide uses throughout for what belongs to the keyboard.
\end{caution}

The tempo message is refused in both directions on the rack: it will neither act on one
received nor send one.

\begin{note}{Telling the two apart over MIDI}
\textsc{md} in anything the instrument transmits is \bytes{00} on the keyboard and
\bytes{01} on the rack --- the values Technics' published field table gives for the two
models. Reading it back takes more than asking, because the two messages that would carry
it in a reply, \textsc{hrq} and \textsc{hrt}, are not an identity enquiry: they are the
opening exchange of a bulk dump (chapter~\ref{ch:bulk}) and are answered only inside it.
The instrument must be showing the \textsc{sysex bulk dump} screen, and \bytes{21} is
answered only while the handshake state is zero, \bytes{22} only while it is one. Sent to
an instrument sitting on any other screen, both produce silence --- and not an
\textsc{err} either, so nothing on the wire separates the wrong moment from the wrong
machine or a dead cable.

What does work at rest is a parameter request (chapter~\ref{ch:params}). Nothing in the
parameter engine consults the panel, so a \textsc{drq} is answered wherever the
instrument happens to be, and the \textsc{itr} that answers it carries \textsc{md}
substituted the same way. A request the instrument refuses is answered too, with
\bytes{F0 50 29 7E F7} --- unlike \bytes{21} and \bytes{22}, which are outside the set
that error reply covers. So the parameter route reports a machine that is listening even
when the address asked for is wrong, which makes it the better probe in both directions.

A third test is behavioural: request a \textsc{sequencer} dump and see whether anything
arrives.
\end{note}

\begin{note}{Which machine is which}
Because the ROMs are identical, the difference between the two models is not a firmware
difference at all. Both behaviours are present in every machine, and a hardware input read
once at power-on selects between them; the program names neither model. The identification does not depend on that, because Technics
published the answer: the field table gives \textsc{md}~=~\bytes{00} for the SX-WSA1 and
\bytes{01} for the SX-WSA1R, and the machine that reads the second value is the one that
transmits \bytes{01}.

The same guide prints \textsc{sequencer : wsa1 only} beside the \textsc{sequencer} row of
its address map. Its user manual marks the whole sequencer chapter \textsc{sequencer
(wsa1)} and carries the same \textsc{(wsa1)} marker on fifty-nine further passages. A
model with no sequencer has nothing to put in a \textsc{sequencer} dump and no use for a
tempo message, which is exactly the pair of System Exclusive functions that machine
refuses.
\end{note}
