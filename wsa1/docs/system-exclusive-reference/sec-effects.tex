\chapter{Effects}\label{ch:effects}

A sound carries three effect blocks --- \textsc{effect1}, \textsc{effect2} and
\textsc{reverb} --- and each is a \textsc{type} byte followed by twenty \textsc{value}
bytes, an \textsc{another eff send} and a \textsc{dynamic control}. The \textsc{type} byte
selects one of 56 effects, and what the twenty \textsc{value} bytes mean depends entirely
on which.

\section{What the type byte selects}
The numbers are not contiguous: they are grouped, with modulation effects below
\bytes{10}, reverbs at \bytes{10}--\bytes{1B}, distortion and dynamics at
\bytes{20}--\bytes{27}, a second modulation group at \bytes{30}--\bytes{38}, two-effect
combinations at \bytes{40}--\bytes{4B} and three-effect combinations at
\bytes{60}--\bytes{63}.

Twelve of the reverbs are marked \textsc{(rev only)} in the published guide: they are
intended for the \textsc{reverb} block rather than \textsc{effect1} or \textsc{effect2}.

\begin{note}{Two sources agree on which effects exist}
The table below was transcribed from the guide. Independently, this project
disassembled the effects DSP and produced a manifest of every distinct effect program
with the number that selects it. The two sets of numbers are equal --- 56 effects,
no more on either side --- which is what makes the numbering here trustworthy.

They disagree only in spelling, because the ROM carries the short names the instrument
displays and the guide prints long ones. The table gives the guide's.
\end{note}

\section{What the value bytes mean}
Each parameter below is printed with the \textsc{value} byte it occupies, in bold. Those
numbers are the guide's own: every \textsc{dsp effect} page carries a \textsc{midi value}
column giving each row's byte outright. An effect that uses fewer than twenty leaves the
rest unused.

\begin{caution}{A parameter is not always one byte, and a byte is not always one parameter}
It is tempting to read the parameter list as the byte order --- first name
\textsc{value1}, second \textsc{value2}. That is true of 34 of the 56 effects and wrong
for the other 22, so a librarian built on it addresses those 22 incorrectly.

Two things break it. A parameter with a wide range spans \emph{two} bytes: \textsc{single
delay} reaches 350\,ms and its \textsc{delay l} is bytes 1--2, which pushes everything
after it up by one. And several parameters can \emph{share} a pair: each band of
\textsc{parametric eq} names an \textsc{fc}, a \textsc{q} and a \textsc{g}, and all
three are packed into the same two bytes by the guide's table~17. \textsc{parametric eq}
has 19 parameters and 13 \textsc{value} bytes.

Where a span like \textbf{2--3} appears against more than one parameter, those parameters
share those bytes; the packing tables at the end of this chapter give each field's width
and position.
\end{caution}

The combination effects concatenate their components: the first block's parameters, then
a dry/wet for the second block, then the second block's. A three-effect combination
continues the same way.

\begin{caution}{The names are transcribed, and not checked by anything}
The effect \emph{numbers} are confirmed twice over, and the byte numbers check themselves:
each effect's must be exactly $1\ldots N$, used once each in ascending order, which a
misread digit almost always breaks. The \emph{names} have no such check --- they were read
from scans, nothing independent states them, and a misreading would survive. Treat them as
a guide to what the bytes are for rather than as a specification.

The block diagram the guide prints for each effect is not reproduced either.
\end{caution}

\section{From a byte to a quantity}\label{sec:conversions}
A \textsc{value} byte is not a quantity. The tables below turn one into seconds, hertz,
decibels or cents. Which table applies is printed in the table above as a superscript
against each parameter: \textsc{high dump gain}~\textbf{8}$^{*2}$ is byte~8, read through
table~2. A parameter with no superscript needs no table --- the range beside it in the
guide is already the quantity, and the byte carries it directly.

Of the 435 parameters, 159 take a table and 276 are direct. The assignment is the guide's
own: each \textsc{dsp effect} page carries a \textsc{midi} column pair, and while the
\textsc{value} column gives the byte number, the \textsc{data} column beside it names the
table.

\begin{note}{One parameter where the guide contradicts itself}
Effect \bytes{47}, \textsc{peq + chorus}, prints no table against its \textsc{lfo speed}
and no \textsc{hz} against its range. The same parameter with the same 0--40.2 range
carries table~3 and the unit on all eleven other pages that have it. The table above prints
what page 27 prints; a librarian would do better to treat it as table~3 like its
siblings.
\end{note}

Each row gives a span of parameter values, the quantity at each end of it, and the step
between one parameter and the next.

Three of the guide's tables are not conversions at all but \emph{packings}: they say how
several fields share two bytes. Those are given at the end, with each field's width.

\begin{note}{The tables check themselves, twice over}
The four numbers in a row are not independent: the first value plus the step times the
span must equal the last. All 41 rows satisfy that identity, and a misread endpoint or
step would break it.

The packings check themselves differently. A field's width must be wide enough for the
range of the table it carries, and each one is exactly wide enough --- five bits for a
parameter reaching 31, five for one reaching 26, six for one reaching 48.
\end{note}
