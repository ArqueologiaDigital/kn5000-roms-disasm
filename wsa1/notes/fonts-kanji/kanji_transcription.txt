# WSA1R private kanji encoding -- a TRANSCRIPTION of the two ideograph faces
#
# QUESTION THIS ANSWERS: prom_a's headers on LCD_Svc_1A / LCD_Svc_1F say
# "the ENCODING ... prom_a cannot say which ideograph a given code is".
# This file says which, by READING THE RENDERED GLYPHS.
#
# PROVENANCE AND GRADE.  Every character below was read by eye from
# prom_b/images/fonts/Font_Svc1A_16x16.png and Font_Svc1F_16x16.png -- the
# lossless contact sheets that scripts/build/wsa1_fonts.py round-trips against
# the ROM.  This is HUMAN OCR OF A 16x16 BITMAP, not a decode: it is the
# weakest link in anything built on this file, and a handful of the readings
# are genuinely ambiguous at this resolution.  Treat a single character as a
# ranked reading, not a fact.  Errors are NOISE, not bias: any statistic run
# over this table is CONSERVATIVE, because a misread character can only break
# a word that is really there, never invent one.
#
# `〓` = one cell whose reading could not be settled (set A 0x38: a 貝/耳-like
# left component with a 戈-like right one; 賦 / 賊 / 職 all fit badly).
#
# Cell counts are the ROM's, and they check out exactly: 224 defined cells in
# set A (codes 0x10-0xEF) and 43 in set B (0x10-0x3A), per
# notes/font_layout_check.py.
#
